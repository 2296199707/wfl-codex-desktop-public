## 需求与边界

用户要求通过本站中转，在浏览器中登录其他服务器，并提供可分享的链接。随后明确：管理员在本站配置服务器，接收者只输入本站设置的访问密钥，即可使用已配置的服务器，不需要再输入远程 SSH 凭据。

- 管理入口使用本站已有登录，管理员可选择自己保存的加密密码模式持久 SSH 服务器，或独立配置目标及密码/私钥。
- 分享入口只输入本站访问密钥；每个密钥绑定一台服务器，本站使用服务器端保存的 SSH 凭据连接。
- 访问密钥等同对应远程账号的完整终端权限，页面明确提示只分享给可信的人。密钥不授予主站管理或其他服务器权限。
- SSH 密码和私钥仅在本站加密保存，不进入链接、不返回浏览器、不写入日志。
- 真正交互式 PTY，支持终端输入、复制粘贴、调整大小、Ctrl-C，以及手机辅助按键。
- SSH 流量由本站发起，浏览器只连接本站 HTTPS/WebSocket，不要求客户端直连目标 IP。
- 分享链接与访问密钥分开：链接打开统一 SSH 登录页，密钥由对方在页面输入。密钥支持有效期和撤销，可自动生成或由管理员设置，服务端只保存带服务器主密钥的摘要。
- 已保存服务器沿用已记录的主机指纹；新目标先读取指纹供管理员确认，再验证及加密保存凭据。指纹不匹配时拒绝连接。
- 用户手动断开或撤销分享时释放远端 SSH 连接；新增版本支持短暂断网后的原终端恢复。主站后端重启或切换时仍无法保留进程内 SSH client，因此本次按用户要求保留运行服务，暂不部署。
- 保持现有 AI SSH 插件的授权和行为、冻结的备用窗口不变；持久 SSH 仅增加独立人工终端连接方法和入口。本次先实现，不擅自提交、推送或部署。

## 使用方式与入口

1. 管理员打开主站工具箱「其他」→「网页 SSH」，管理地址为 `/ssh.html`。
2. 选择可用于终端的持久 SSH 服务器，或点击「添加服务器」，填写名称、IP/域名、端口、用户名及密码/私钥。支持加密私钥的口令；先确认主机指纹，再验证及保存。
3. 为所选服务器创建访问密钥：自定义或自动生成，有效期可选 1 小时、1 天、7 天或长期。每台服务器可以创建多个独立密钥。
4. 复制登录链接和访问密钥；分享页面为 `/ssh-access.html`。接收者只输入访问密钥，不需要主站登录、不需要填写服务器地址或 SSH 凭据。
5. 管理页可以撤销密钥，也可以删除独立配置的服务器。对应终端会断开，已签发但未使用的票据也不能绕过撤销。

持久 SSH 记录还增加了网页终端按钮。人工连接与 AI 插件开关独立，关闭 AI 可见性或停用 AI 插件不会关闭人工终端；删除对应持久 SSH 配置会关闭人工终端。

## 必须保留的兼容边界

- 原 AI 公钥在远端 `authorized_keys` 中带有 `no-pty`，不能提供交互式终端。没有放宽、替换或重新安装这些公钥。公钥模式的持久记录在网页 SSH 页明确标为需要另配终端凭据；从记录打开时自动填入服务器信息，但不会改选其他服务器。
- 网页 SSH 访问密钥不是 SSH 私钥，也不是主站管理密码。它对应配置账号的完整远端权限；如绑定 root，持有者就有该服务器的 root 终端权限。
- 分享密钥不包含在 URL 中，不进入浏览器存储。服务端保存 HMAC-SHA256 摘要；SSH 凭据使用独立主密钥进行 AES-256-GCM 加密。
- 分享登录不建立主站会话、不返回主站 Cookie；分享页 HTTP 请求不携带已有主站 Cookie。WebSocket 只接受一次性票据，票据放在首帧而非 URL 中。
- 撤销本进程的密钥立即关闭对应连接；到期、账号权限失效、其他进程改变授权时，最多 5 秒重新检查一次。管理员退出登录会关闭其已绑定主站会话的终端，不影响已单独授权的访客终端。
- 终端传输使用带输出确认的流控，避免慢客户端累计无限内存；没有添加命令白名单、命令执行时限或空闲终端强制退出。
- 主站切换后关闭 SSH 连接，用户手动重连；不会自动重放命令。原主站对话 WebSocket 的切换/恢复逻辑不变。
- 本次没有新增 AI MCP 工具，不让 AI 自动读取访问密钥或共享服务器凭据。

### 0.45.3 管理页 404 修复

- 工具箱与持久 SSH 入口改用原生链接，消除 `noopener` 导致 `window.open` 返回 null 时的拦截误报。

## 断线与自动恢复（2026-10-01）

用户随后要求继续，并询问连接容易断线、能否自动重连。检查近 90 分钟日志未发现主站/网关重启，两者从 2026-09-30 部署后持续运行。Nginx 的 WebSocket 读写超时为 3600 秒。源码确认两个容易放大网络波动的行为，但现有日志不足以断定每次实际断线的网络原因：

1. 原服务在浏览器 WebSocket close/error 时直接结束远端 SSH client 和 PTY。手机切后台、网络切换或短暂断网会结束终端，前端也没有恢复机制。
2. 共用连接器默认 5 秒一次 SSH 保活、容忍 2 次未回应，持续约 10 秒无响应就可能断开。新版本仅把人工终端连接改为 15 秒一次、容忍 6 次，原 AI SSH 默认值保持不变。

新的恢复机制：

- 已就绪终端获得独立恢复凭证，仅保存在当前页面内存里，绑定原会话和原授权，不保存 SSH 密码或访问密钥。
- 浏览器意外断开后保留原 SSH client/PTY 5 分钟。输出使用原有流控暂停，在恢复后继续送出；不重新运行命令，也不缓存或重放断线期间的输入。
- 页面按 1、2、4、8、15 秒间隔尝试恢复原会话；网络恢复或页面回前台会触发恢复检查。恢复时不清空已有终端画面，不创建第二条远端 SSH 连接。
- 不能抢占仍在线的同一终端。手动断开会取消重试并结束此会话；过期、撤销、权限失效仍按原规则生效，也会取消文件传输和下载票据。
- 远端 shell 已退出、SSH 本身已断开、主站后端重启/版本切换、页面刷新丢失内存凭证或超过保留期限时，不能恢复原进程，页面提示重新登录。没有宣称自动恢复可以跨服务重启保留命令。
