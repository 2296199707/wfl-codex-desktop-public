# 工作区迁移

工作区迁移用于把拥有者选中的工程文件和关联对话复制到另一台
WFL Codex Web Workspace 服务器。源服务器只读取并生成快照；迁移完成后，
源服务器与目标服务器彼此独立，均可继续使用。

## 源服务器

1. 打开“管理员运维中心 > 迁移”。
2. 选择工程以及 Git 历史、`.env` 范围。
3. 输入所有者密码并生成迁移包。
4. 分别下载 `.wflworkspace` 文件和恢复密钥文本。

迁移包采用 AES-256-GCM 加密。恢复密钥包含迁移包编号和 SHA-256，
只对对应迁移包有效。迁移包和恢复密钥应分开保存和传输。

## 目标服务器

1. 安装 `v0.36.0` 或更高版本并打开“管理员运维中心 > 迁移”。
2. 选择 `.wflworkspace`，输入所有者密码并上传。
3. 粘贴恢复密钥并执行预检。
4. 检查目标工程名称，输入迁移包编号和所有者密码后确认导入。

上传按 8 MB 顺序分块进行。连接中断后，在当前网页重新点击上传会从
服务器记录的位置继续。同名工程不会被覆盖，而是自动使用
`-migrated`、`-migrated-2` 等新名称。

## 数据范围

包含：

- 选中的工程源码、文档、资源和工程内上传文件。
- 选中工程的活动对话和归档对话。
- 可选的 Git 历史和 `.env` 文件。
- 安装目录工程会以 `Codex-Desktop-workspace` 作为目标工程名导入，不会覆盖
  目标服务器自己的 WFL Codex Web Workspace 安装目录。

不包含：

- 用户账号、密码、会话和套餐。
- API 供应商、密钥和官方 Codex 登录。
- Cloudflare、systemd、SSH、发布状态和临时运行数据。
- `node_modules`、`.codex-desktop`、`.codex-runtime`、符号链接和特殊设备。
- 安装目录工程中的发布备份、覆盖率结果、浏览器测试结果和发布包元数据。
- 尚未完成任务的进程状态。

新版迁移清单会记录源运行用户的 UID/GID 和每个工程根目录模式。预检会校验
tar 中每个目录与文件的数值属主、普通权限模式、类型和大小，再与私有解包目录
逐项核对；setuid、setgid、sticky 特权位、混合属主和无效 UID/GID 会被拒绝。
复制到目标工程后还会按目标运行用户再次核对属主和模式。不同服务器可以使用
不同的数值 UID/GID，导入以目标服务器运行用户为准，不会照搬源服务器属主。

导入先在私有目录解密和预检，再新建目标工程和对话。任一步失败时，
本次新建的目标内容会被清理；目标服务器原有工程不会被覆盖或删除。
