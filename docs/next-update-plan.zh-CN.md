## 1. 本版本结论

`v0.43.57-beta` 应交付以下结果：

1. 第三方子代理使用官方 DeepSeek `SubagentRuntime`：独立 child、后台继续、后续消息、中断、列表、settlement 和冷恢复；不暴露或执行 WFL 自定义任务预算。
2. 角色动作编辑器从“能创建和保存基础清单”收敛为可靠的基础编辑闭环：不会因工程/角色切换或 `409` 冲突丢稿，支持撤销重做，以及动作和帧的完整基础编辑。
3. 主界面的“工具箱 · 游戏编辑器”从长面板收敛为清晰的工程工具工作区：主操作、资源、AI 协作和状态反馈分层，角色编辑器联动可预期。
4. 已完成的资源管理器目录标题修复被对齐进 Git 工作树并通过定向复核。
5. 发布后只可宣称“角色编辑器基础编辑闭环完成”和“工具箱基础工作区优化完成”，不能宣称角色运行时、AI 角色工具、碰撞系统或完整角色制作系统已经完成。

## 2. 目标与非目标

### 2.1 目标

- 对齐官方 Codex 子代理的独立 agent-thread、摘要回传和显式生命周期语义，同时保留 WFL 的供应商路由、父线程权限继承和工程写入哈希校验。
- 删除单个第三方线程的回合、工具、排队和累计执行预算，避免任务已消耗 Token 后被本地阈值截断。
- 保证模型最终结果、错误、停止和重复工具循环状态如实返回，不用自定义结构化终态协议替代模型摘要。
- 让工具箱入口打开的角色编辑器具备可恢复、可验证、可保存的基础创作流程。
- 让主界面工具箱在工程、资源、地图、角色和 AI 协作之间提供清晰的操作层级、状态反馈和安全边界。
- 在桌面、窄屏和键盘操作下均能完成动作与帧的基础 CRUD，不把拖拽作为唯一操作方式。
- 保持管理员对话访问、父线程隔离、工程授权和现有写入权限边界不变。

### 2.2 非目标

- 不允许第三方子代理创建孙代理、绕过父线程审批、扩大工程范围或取得额外系统权限。
- 不把供应商月额度、Token 用量或执行进度包装成 WFL 任务预算。
- P0 不实现角色图片生成/扩图、完整导入导出、AI 托管、角色补丁工具目录或自动发布。
- P0 不修改 `/srv/wflgame`，不声称游戏运行时已经消费角色方向、锚点或语义框。
- P0 不实现碰撞框、攻击框、受击框、交互框、武器锚点或复杂动作事件。
- 不运行完整仓库测试、压力测试或通用浏览器 smoke；只运行与改动直接相关的有界检查。
- 不读取、修改、重启、升级、启停或切换救援窗口，不触碰 `rescue-active-port`、救援槽位或 `4321`。

## 6. P0-S：第三方子代理官方 runtime 接线（历史记录，已归档）

本节只记录当前实际实现和验收边界，不把旧 WFL 子代理方案继续当作待实现设计。

### 6.1 官方参数和父会话上下文

- MCP `subagent` 只接受 `description`、`prompt` 和 `run_in_background`；控制工具只接受
  官方 child id、消息或列表范围。
- 不接受或展示 `maxTurns`、`maxTotalTurns`、`maxToolCalls`、`maxDurationMs`、
  `maxQueueDurationMs`、角色、费用或 Token 预算。
- 子代理启动前验证父 thread/turn 元数据、绝对 cwd、sandbox 和 approval；`ask/on-request`
  当前因无完整跨进程审批桥而 fail closed。
- 官方 runtime 保存 child 的 provider、session、inbox 和 parent ownership；WFL 只保存
  每用户 Host binding 和传输所需的短期连接信息。

### 6.2 官方生命周期和结果

- `run_in_background=true` 使用官方 continuable child，立即返回 durable child id；官方
  runtime 负责后续 `send_message`、`interrupt_agent`、`list_agents`、settlement 和冷恢复。
- `run_in_background=false` 是显式前台 one-shot，完成后由官方 runtime 回收临时 session。
- 多个 child 可以并行运行；每个 child 的 session、工具和 settlement 保持隔离。
- WFL 不引入 `wait/continue`、`needs_continuation`、自定义 `close/tombstone` 或第二套
  终态机；返回官方最终文本、错误或 stop reason。
- child 归属由官方持久化 `parentSession` 再经 Host Bridge 校验；跨父会话控制必须拒绝。

### 6.3 供应商切换与恢复

- 运行中的官方 runtime 是其 child 的 provider 所有者；配置变更不会立即停止旧 runtime。
- 控制已有 child 时继续使用仍存活的旧 runtime；新任务只有在官方 `list` 确认所有持久
  child `activity` 都是 `inactive` 且无未完成请求后才切换。
- 官方列表失败、出现 diagnostic 或状态未知时 fail closed，保留旧 runtime，不猜测放行。
- runtime 重启后只按已保存 Host binding 和官方 persistence 恢复；没有可验证上下文时拒绝。

### 6.4 P0-S 验收

- `deepseek-harness-subagent` 定向测试 `30/30` 通过；覆盖两种 OpenAI 兼容协议、工具写入、
  只读沙箱、并发、断连取消、父子归属、settlement、冷恢复和供应商切换。
- MCP schema 不包含 WFL budget、role、credential、thread ownership 或模型循环参数。
- 真实第三方模型不作为普通开发步骤调用；只有明确的真实功能测试才允许调用，并单独
  记录请求次数、工具调用和结果。

## 7. P0-C：角色编辑器可靠基础闭环

### 7.1 统一编辑状态

把编辑状态明确拆成：

- 已保存服务端版本和已保存文档指纹；
- 当前已验证文档；
- 尚未通过模型校验的输入草稿；
- 撤销栈、重做栈和当前选择；
- `dirty`、`invalidDraft`、`saving`、`loading` 和冲突状态。

规则：

- 只要模型内容已变或输入草稿尚未验证，均视为“有未保存修改”。
- 校验错误不清除当前已验证文档，但保存按钮禁用、错误可见、切换保护仍生效。
- 动作或帧选择只是同一文档内的视图切换，不弹未保存确认。
- 打开/刷新工程、切换角色、新建角色及任何会替换整个文档的操作，统一经过“保存 / 放弃 / 取消”守卫。
- 选择“保存”后只有保存成功才继续原操作；`409`、网络错误或校验错误均保持当前文档和选择。
- 取消角色下拉切换时，选择框恢复为当前角色，不能显示尚未实际载入的路径。
- `beforeunload` 继续作为最后保护，但不能替代应用内守卫。

### 7.2 `409` 冲突恢复

- 客户端根据 HTTP status 和结构化 error code 判断冲突，不再依赖中英文正则文本。
- 冲突发生后保留本地文档、输入草稿、撤销历史、当前选择和 dirty 状态。
- 冲突面板显示目标路径、本地基础版本、服务端最新版本和冲突类型。
- 提供以下安全动作：
  - 继续编辑：关闭面板，不改变本地数据；
  - 复制或下载本地草稿：便于人工备份；
  - 另存为新的 `.character.json`：使用创建语义，目标已存在时继续拒绝覆盖；
  - 重新载入服务器版本：二次确认后替换本地草稿并重置历史。
- P0 不自动合并、不提供无版本强制覆盖，也不把 post-commit conflict 当成普通成功。

### 7.3 撤销与重做

- 每个语义操作形成一个历史事务；连续文本输入应合并，不能每个按键创建一份完整历史。
- 历史同时受条目数和字节数限制，超限从最旧记录开始压缩或丢弃。
- 新建/载入文档时重置历史；保存成功只更新保存基线，不抹掉保存后的新编辑。
- `409`、保存超时和网络失败不能清空历史或改变保存基线。
- 支持按钮及 `Ctrl/Cmd+Z`、`Ctrl/Cmd+Shift+Z`；输入框原生撤销与文档级撤销的焦点行为必须明确。
- 撤销/重做后恢复有效的动作和帧选择，并重新执行模型校验与预览。
- 未知字段在编辑、撤销、重做和保存往返后仍保留。

### 7.4 动作与帧完整基础编辑

动作片段支持：

- 新建、复制、删除和上移/下移；
- 稳定且唯一的动作 ID；
- 名称、循环、方向和帧列表；
- 至少保留一个动作，删除当前动作后选择确定且可预测。

时间轴帧支持：

- 新建、复制、删除和上移/下移；
- 拖动排序作为增强交互，但同时保留可聚焦按钮和键盘操作；
- 帧索引与逐帧时长编辑；
- 至少保留一帧，所有索引均在精灵图网格范围内；
- 排序后播放头、选中帧和时长仍对应同一帧记录。

方向与播放：

- UI 提供 `forward`、`reverse`、`pingpong`。
- `clipFrameAt` 实现三种方向在循环和非循环模式下的确定性状态机。
- `pingpong` 边界帧是否重复必须固定为一种规则并由单元测试锁定。
- 切换动作、方向或循环时停止旧播放并重置到可预测起点。

### 7.5 从精灵图选帧

- 增加可点击的精灵图网格选择区，显示网格边界、当前选中单元和帧索引。
- 明确区分“替换当前帧”和“追加到当前动作”，避免单击产生隐式破坏性行为。
- 网格使用与保存模型相同的 margin、spacing、rows、columns 和 frame size 计算。
- 图片尺寸、网格越界或未加载完成时拒绝选帧并显示具体错误。
- 点击、键盘和触控均可完成最小操作；大图片只缩放显示，不重采样或改写原图。

### 7.6 异步、窄屏和可访问性

- 工程、角色、图片、保存和冲突刷新各自使用明确的请求 generation；旧回调不能覆盖新文档。
- 保存期间的新编辑继续保留 dirty；保存响应只能更新它实际提交版本的保存基线。
- 所有图标按钮有可见名称或 `aria-label`，对话框具备焦点圈定和关闭后焦点恢复。
- 排序不能只依赖拖拽；移动端按钮具备足够触控区域，窄屏下动作、时间轴和预览仍可到达。
- 校验、冲突和保存状态使用可读的状态区域，不用颜色作为唯一提示。

### 7.7 P0-C 验收指标

- 打开/刷新工程、切换角色和新建角色均不能在无确认时丢失有效或无效草稿。
- `409`、网络失败和保存超时后，本地草稿、历史和 dirty 状态保持不变。
- 保存期间继续编辑时，保存成功只清除已提交部分的 dirty 基线，新编辑仍可再次保存。
- 动作和帧的新建、复制、删除、排序均可撤销和重做。
- 三种播放方向在变长帧时长、循环和非循环组合下通过确定性单元测试。
- 从网格选帧后，保存并重新打开得到相同动作、顺序、时长和方向。
- 未知字段经过编辑—保存—重新打开后仍保留。
- 键盘和窄屏流程不依赖拖拽即可完成最小编辑。
- 工具箱入口、工程授权、版本校验和安全相对路径保持不变。

### 8.5 P0-T 验收指标

- 打开工具箱后，用户能在一个视图内确认当前工程名称、路径、读写状态和连接状态。

## 13. 迁移与兼容

### 13.1 子代理

- 旧 `maxTurns`、累计预算、角色和自定义 continuation 字段不再接受，调用方必须删除这些参数。
- MCP 调用改用官方 `subagent`、`send_message`、`interrupt_agent`、`list_agents` 语义；不再提供旧 `programming_*` 工具。
- 已存在的官方 durable child 由其 runtime persistence 和 Host binding 恢复；无法验证父级或 provider 所有权时拒绝，不串到其他父对话。
- provider 设置仍复用普通供应商的模型、Base URL、API Key 和协议；WFL 不另设子代理预算或独立额度。
- 当前 approval、真实 app-server 重连和跨进程恢复边界必须如实保留为未完成验证，不能用兼容入口掩盖。

### 13.2 角色编辑器

- P0 保持 `wfl.character-animation.v1`，不引入必须由旧运行时理解的新语义框。
- 未知字段继续保留；方向字段已有兼容默认值 `forward`。
- 旧文档没有方向字段时按 `forward` 读取，保存后行为稳定。
- 冲突恢复不引入强制覆盖接口，不改变服务端版本比较规则。
- P1 若需要新增语义框，必须先单独定义 schema 兼容和运行时能力策略。

### 14.3 回滚

触发条件包括：

- 子代理再次出现本地预算硬截断、状态误报、协议历史损坏或父线程串线；
- worker 写权限或哈希冲突边界回归；
- 角色草稿丢失、`409` 被覆盖、保存版本基线错误；
- 新前端资产缺失、候选健康失败或管理员对话无法访问。

回滚只切回已验证的旧主站槽位和旧主站代码，不回写用户角色文件，不删除恢复现场。角色 P0 保持 v1 schema，回滚不需要批量降级角色数据。

救援窗口是独立冻结组件。普通开发、候选、发布、回滚和恢复均不得修改 `rescue-active-port`、`4321`、救援服务、救援槽位链接、救援资产或救援组件版本。
