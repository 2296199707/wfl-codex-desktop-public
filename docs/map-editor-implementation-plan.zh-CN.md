- 状态：长期实施方案
- 初始规划基线版本：`0.43.27-beta`（历史基线）
- 当前已部署版本：`0.43.54-beta`；`0.43.55-beta` 为本轮 Goal 终止确认修复候选，验证通过后才切换主站。
- 编写日期：2026-08-11
- 当前文档核对：2026-08-14
- 协同方案增补：2026-08-13～2026-08-14（阶段 11，持续实施）

正文中出现的 `0.43.27-beta`、`0.43.35-beta` 和其他更早版本号，均属于对应阶段的历史实施记录；当前运行状态以本节和最新

架构依据：[ADR-0004：浏览器地图编辑器、地图存储与隔离渲染边界](adr/0004-browser-map-editor.zh-CN.md)

## 1. 文档目的

本计划把当前“按单个 `.tmj` 打开的地图编辑器”逐步建设成面向完整游戏工程的浏览器地图工作区。
它同时覆盖产品界面、Tiled 兼容、图片编辑、素材复用、AI 协作、后台任务、手机和平板、可靠性、
安全、性能、测试及发布。

本文是实施路线图，不替代 ADR-0004。ADR-0004 继续作为文件、权限、原子保存、Worker、队列和
AI 租约的安全边界；本文负责说明在这些边界内先做什么、如何拆分、怎样验收，以及何时可以称为
“可用于完整游戏地图制作”。

## 2. 已确定的产品原则

以下原则在全部阶段中保持不变：

- 采用浏览器原生界面，不采用 Linux 桌面远程控制。
- 以 Tiled JSON 为主格式：地图使用 `.tmj`，外部瓦片集使用 `.tsj`。
- HTML、地图、瓦片集、图片、音频和生成结果保持独立文件，不把工程打包进单个 HTML。
- 图片不能以 Base64、data URI、远程 URL 或供应商 File ID 嵌入地图。
- 未识别的 Tiled 字段和值必须原样保留，不能因为 WFL 暂时不会编辑就删除或重建。
- 不新增单独的“整图模式”。完整背景图使用图片层，瓦片、对象和碰撞按需叠加在同一编辑器中。
- 浏览器负责实时画笔、选择、拖动、缩放、图层和撤销；主站负责授权、隔离、版本和原子保存。
- 高清截图、全景、切片、动画、视频、批量导出和图片后处理在独立 Worker 中执行。
- Worker 离线、失败、超时或超过内存预算不能影响聊天主站、浏览器编辑或地图保存。
- 管理员手动设置并发、内存、缓存、超时、预览和导出参数；系统不得自动切换预设或降低质量。
- 达到手动并发或队列上限时排队或明确拒绝新任务，运行任务保持入队时的参数快照。
- 普通 Codex 和 Claude 对话继续发送用户明确附加的完整图片。
- 只有当前游戏工程、线程、主窗口、地图窗口和租约全部匹配时，才启用游戏图片上下文隔离。
- 地图 AI 工具权限与游戏图片隔离是两个独立开关，默认都不自动开启。
- AI 默认以结构化提案工作：用户可以预览、分批接受、拒绝或撤销，提案不会自动保存。
- 增加独立的“AI 托管地图模式”：用户在主界面明确授权工程、地图、操作类别和有效期后，AI 可以直接应用经过
  版本、格式、路径和运行时校验的补丁；托管模式也不能绕过原子保存、审计、冲突保护和恢复记录。
- 编辑器协作与 AI 托管共用同一份 Tiled 文档模型、版本服务和保存事务，但权限、交互和责任边界必须始终可见，
  系统不得自动在两种模式之间切换。
- 不自动向对话注入地图全文、图片、提示词或工程目录，避免增加 Token 和串工程、串线程。
- 第一阶段不引入 Yjs，不实现多人同时共同编辑同一文档。
- 主站发布必须递增版本并走现有蓝绿流程；冻结的救援组件 `4321` 不属于本计划的修改范围。

## 3. 用户与核心场景

### 3.1 新手用户

新手应当可以不理解 GID、Wang Set 或 tile data 编码就完成以下流程：

1. 从主界面进入当前游戏工程的地图工作区；
2. 新建地图或打开已有地图；
3. 拖入一张完整背景图片；
4. 调整图片位置、图层顺序和透明度；
5. 添加碰撞、出生点、传送点和互动对象；
6. 在需要大量重复地形时再使用瓦片；
7. 预览、保存并运行游戏。

界面可以使用“瓦片”“图层”等 Tiled 标准术语，但必须用清楚的中文名称、图标、状态和工具提示，
不能要求用户先阅读格式文档才能完成基本操作。

### 3.2 瓦片地图制作者

熟悉 Tiled 的用户应当可以使用外部 `.tsj`、无限地图、Terrain/Wang Set、对象模板、自定义类型、
自动映射和 `.world`，并能在 Tiled Desktop 与 WFL 之间往返保存而不丢字段或改变语义。

### 3.3 AI 辅助制作者

用户可以在主界面或地图编辑器右侧使用同一个工程对话，选择“只读检查”“编辑器协作”或“AI 托管”来要求 AI
检查地图、生成素材、提交修改提案或在授权范围内直接完成修改。新手不需要理解租约、哈希或 MCP 参数，界面必须
把“这次 AI 能做什么、会改哪些文件、谁负责确认”翻译成清楚的中文状态。

AI 只按需读取有限地图区域和资源元数据；图片、地图全文和任务结果不会因为显示在界面中而自动进入长期对话
上下文。即使用户授予托管权限，AI 也只能通过结构化地图工具写入，不能把通用文件写入能力伪装成地图编辑器。

### 3.4 桌面、平板和手机用户

桌面提供完整三栏工作区；平板保留完整编辑能力并使用可收起面板；手机提供画布、图层、工具、对话
和任务的全屏标签/底部抽屉，不提供功能被删除的“简化画质模式”。

## 4. 当前基线与缺口

### 4.1 `0.43.27-beta` 已具备

- Tiled JSON 解析、校验、序列化和未知字段保留；
- `.tmj`、外部/内嵌瓦片集、工程相对资源和资源授权；
- 正交、等距、交错、六边形和 Tiled 1.12 oblique 投影；
- 有限地图和无限地图 chunk；数组及 Base64 tile data，gzip/zlib 和运行环境可用时的 zstd；
- 瓦片层、对象层、图片层、分组层及嵌套组；
- 图集瓦片集、图片集合瓦片集、GID 范围、翻转标志和瓦片动画播放；
- 图层新增、复制、移动、删除，单瓦片画笔、橡皮、填充和矩形选区；
- 矩形对象、碰撞、出生点、传送点、对象拖动和基本属性；
- 撤销/重做、版本哈希、`409` 冲突、分段读取和分块原子保存；
- 独立 Render Worker 的地图截图、游戏截图、全景、切片、动画、视频和批量导出；
- 独立图片 Worker 的生成、编辑、蒙版和四向扩图；
- 显式地图 AI 租约、提案收件箱、预览、应用和手动保存；
- 默认关闭、可独立用于任何对话的图片上下文隔离；
- 桌面、平板和手机的基础地图界面。

### 4.2 当前不能称为完整的原因

- 入口仍以单个 `.tmj` 为中心，不能把当前工程作为完整 Tiled 项目打开；
- 没有 `.tiled-project`、`.world`、多地图标签、新建地图和完整项目文件树；
- 工程中的多张 PNG 不会一次成为对齐的多个图片层；
- 图片层只能输入偏移，不能在画布上直接拖动、对齐、裁剪或用辅助线扩图；
- 图片重复、视差、色调、混合模式和部分 Tiled 渲染语义只保留字段但不正确预览；
- 瓦片工具只覆盖基础单格绘制，没有多格 stamp、随机、Terrain/Wang、形状填充和高级选择；
- 对象能显示多种形状，但创建和编辑主要停留在矩形、点状预设和整体移动；
- 没有完整 `.tsj` 编辑器、tile collision、tile animation、terrain set 和 probability 编辑；
- 没有工程级 Class、Enum、List 类型、自定义属性专用控件和对象模板继承；
- 没有 Automapping；
- 地图编辑器没有右侧同线程对话、同项目线程切换和统一任务小窗。
- AI 工具仍以编辑器窗口租约为前提，不能在不打开编辑器时由用户授予受限的托管直写权限；
- 没有把人工的保护区域、锁定图层、批次审批、任务接管和托管修改恢复统一进一个协同协议。

## 5. Tiled 兼容目标

### 5.1 兼容基线

实现和测试以 Tiled `1.12.2` 为当前明确基线。后续 Tiled 小版本新增未知字段时，WFL 应继续无损保留；
新增已知语义必须通过单独能力实现和夹具验证，不能仅通过更新 `tiledversion` 宣称兼容。

当前解析、渲染、编辑和保存支持等级以
[Tiled 1.12.2 兼容矩阵](tiled-1.12.2-compatibility-matrix.zh-CN.md)为准。

### 5.2 工程文件模型

| 文件/目录 | WFL 目标语义 |
| --- | --- |
| `.tiled-project` | 工程资源目录、兼容版本、Automapping 规则和自定义类型的权威定义 |
| WFL 用户会话状态 | 记录每个用户的已开标签、画布位置和面板状态，不把共享 `.tiled-session` 当多用户状态 |
| `.world` | 多地图世界位置、尺寸、模式匹配和相邻地图加载策略 |
| `.tmj` | 单张地图或组合素材的 Tiled JSON 文档 |
| `.tsj` | 默认外部瓦片集，供多个地图共享 |
| Tiled 对象模板 | 单对象模板及继承/覆盖；WFL 第一阶段只处理 JSON 内容 |
| `rules.txt` 与规则 `.tmj` | Automapping 规则入口和规则地图 |
| PNG/JPEG/WebP | 独立图片；透明素材优先 PNG/WebP |
| HTML/CSS/JS/音频 | 游戏运行资源，不嵌入地图文档 |

### 5.3 必须无损往返的语义

- 地图、瓦片集、图层、对象、瓦片、Wang Set、属性、模板引用和未知字段；
- `nextlayerid`、`nextobjectid`、firstgid 及所有稳定 ID；
- tile data 原始 `encoding`、`compression`、chunk 布局和 32 位 GID 标志；
- 图层顺序、分组层级、锁定、可见性、透明度、偏移、视差、色调、重复和混合模式；
- 对象矩形、点、椭圆、胶囊、多边形、折线、文字和瓦片对象；
- Tiled 1.12 对象 opacity、图层 `mode` 和 List 属性；
- 固定/无限地图、五种方向、render order、背景色和投影参数；
- atlas 与 image collection 两类瓦片集、tile offset、object alignment、transformations、动画、
  碰撞、属性、probability 和 Terrain/Wang 数据。

### 5.4 有意不做的兼容范围

- 不把 XML `.tmx/.tsx` 设为主编辑格式；可以以后提供显式导入转换，但不能静默改写为 XML。
- 不允许图片、音频或 HTML 使用 Base64/data URI；Tiled 标准 Base64 tile data 仍允许。
- 不执行工程携带的 Tiled JavaScript 扩展。项目扩展目录只作为不可执行资源显示；未来若支持，必须是
  管理员安装和审计后的独立沙箱插件。
- 不复制 Tiled Desktop 的所有窗口、系统文件对话框和第三方导出插件。
- 不在 `.tmj` 中引入只有 WFL 才能解释、且会改变游戏运行语义的私有必需字段。

## 6. 产品信息架构

### 6.1 主界面工具箱与双开关

对话界面顶部原来的“地图”按钮改为“工具箱”。工具箱是当前工程游戏工具的统一入口，不要求用户先打开地图编辑器，
也不把图片分析强行归入游戏流程。建议布局：

```text
工具箱

当前工程：Game Project
当前对话：森林关卡设计

隔离上下文图片                         开关
允许 AI 使用游戏编辑工具                 开关

工具：地图 | 角色编辑 | 瓦片集 | 素材库 | 图片处理 | 预览
状态：图片索引 38 张 · 游戏工具未启用
```

普通用户只需要理解两个独立开关：

| 隔离上下文图片 | 允许 AI 使用游戏编辑工具 | 行为 |
| --- | --- | --- |
| 关闭 | 关闭 | 普通对话，图片按普通附件规则处理，不使用游戏工具 |
| 开启 | 关闭 | 任意项目中的批量图片索引、分析、去重和摘要，不修改游戏文件 |
| 关闭 | 开启 | AI 可以操作当前工程的地图、角色、瓦片集和素材，图片按普通规则处理 |
| 开启 | 开启 | 完整游戏协作，同时限制图片上下文增长 |

要求：

- “隔离上下文图片”只控制图片进入当前 Thread 的方式，适用于游戏、设计、产品、资料审查等非游戏场景；
- “允许 AI 使用游戏编辑工具”只控制当前账号、当前工程和当前 Thread 的游戏工具，不要求地图编辑器或角色编辑器窗口存在；
- 两个开关互不暗中改变对方，均由用户显式开启；切换工程或 Thread 时不能泄漏旧状态、图片哈希或工具上下文；
- 开启图片隔离后可以批量拖入图片或选择目录，AI 先使用资源清单、缩略图联系表和结构化摘要，不要求用户逐张选择；
- 游戏编辑工具包含地图、World、瓦片集、素材库、角色动作编辑器、图片处理、预览和导出，但所有写入仍受工程路径、版本、
  原子保存和可撤销历史保护；不为每个子工具增加单独的普通用户开关；
- 地图编辑器和角色动作编辑器都是工具箱的可选观察/编辑窗口。窗口关闭不关闭开关，窗口打开后同步显示主界面当前
  Thread、任务、版本和差异；
- 托管、风险判定、版本冲突和恢复属于后台固定安全规则。高级审计/授权详情可以折叠显示，但不能成为日常使用前提；
- 不根据图片数量、服务器负载、设备类型或 AI 判断自动切换开关、画质、并发或工具范围；
- 顶部按钮、工具箱标题、帮助文案和移动端入口统一使用“工具箱”，不再把入口命名为“地图”。

### 6.2 地图编辑器桌面布局

```text
顶部：工程名 / 地图标签 / 保存 / 撤销 / 预览 / 导出 / 协作状态

左侧                 中央画布                     右侧工作栏
项目/图层/素材        当前地图或 World             对话
属性/瓦片集                                        AI 修改
                                                   处理任务

底部：坐标 / 瓦片坐标 / 选择 / 警告 / 游戏模式状态 / 保存状态
```

- 项目树与当前地图图层树是两个不同视图；
- 多个 `.tmj` 使用标签页保持打开，未保存状态显示在对应标签；
- 右侧工作栏可收起和调整宽度，但聊天、提案和任务不使用浏览器弹窗作为唯一入口；
- 图片处理任务默认显示为可收起的小任务托盘，用户可显式弹出独立监视窗口；
- 游戏模式在编辑器中保留同步状态图标，点击打开详情；它与主侧栏是同一状态源。

### 6.3 平板和手机

- 平板允许画布加一个停靠面板，其他面板作为抽屉切换；
- 手机以画布为第一屏，图层、属性、素材、对话、AI 修改和任务使用底部标签或全屏抽屉；
- 常用工具保持固定尺寸，触控手柄不能小于可可靠操作的范围；
- 双指只用于平移/缩放，不触发绘制；触控笔可以绘制，手掌触碰不能提交地图操作；
- 手机仍能创建、编辑、预览、应用提案和保存，不自动降低地图或图片质量。

## 7. 状态、权限与窗口模型

### 7.1 状态作用域

| 状态 | 作用域 | 持久性 |
| --- | --- | --- |
| 游戏编辑工具能力（服务端外层） | 用户账号 | 作为安全边界保存，不直接暴露为日常操作 |
| 允许 AI 使用游戏编辑工具 | 用户 + 工程 + Thread | 用户显式开启；窗口可选，不依赖编辑器租约 |
| 隔离上下文图片 | 用户 + 工程 + Thread；无工程时为用户 + Thread | 用户显式开启；只影响当前图片交付策略 |
| 地图编辑会话 | 用户 + 登录会话 + 工程 + 地图 + editorInstance | 短期服务端会话 |
| AI 托管授权 | 用户 + Thread + 工程 + 地图范围 + 操作范围 | 明确授权后的短期租约，可撤销 |
| 人工协同策略 | 当前用户 + 工程 + 地图/图层/区域 | 用户显式保存的协同策略，不自动扩大 |
| 地图托管任务 | 用户 + 发起 Thread + 工程 + 地图 + 配置快照 | 服务端持久任务，直到完成、取消、失败或过期 |
| 撤销、选择、脏状态 | 单个 editorInstance | 仅当前窗口 |
| 对话视图 | 原生 Thread | 主界面和编辑器共同显示 |
| 图片去重和分析记录 | 用户 + 工程 + Thread；无工程时为用户 + Thread | 仅当前对话有效，不要求地图窗口存在 |
| 图片/渲染任务 | 用户 + 工程 + 配置快照 | 服务端任务生命周期 |

### 7.2 同一对话的双窗口显示

- 编辑器右侧不是新聊天系统，而是主界面当前原生 Thread 的第二个受控视图；
- 两边接收同一组官方 Thread/Turn/Item 事件，消息和流式输出一致；
- 任一窗口发送后，另一个窗口立即显示；
- 同一 Thread 同一时刻只接受一个权威回合提交，重复提交使用操作 ID 幂等处理；
- 编辑器关闭不结束对话，主界面关闭但编辑器仍有效时按现有窗口所有权规则恢复；
- 地图编辑器不复制长期对话历史到独立存储。

### 7.3 同项目对话切换

- 只列出当前用户且 `cwd`/工程身份匹配的 Thread；
- 显示标题、提供方、模型、最后活动时间和运行状态；
- 切换前撤销旧 Thread 的游戏租约和地图 AI 租约；
- 新 Thread 完成工程和窗口握手后再开启对应能力；
- 地图标签、画布位置和未保存编辑保持不变；
- 不复用旧 Thread 的图片哈希记录、提案收件箱或工具上下文；
- 有运行中 Turn 时允许观看，但发送和切换必须遵循官方 Thread 状态与审批协议。

### 7.4 普通对话与图片分析不受游戏编辑器影响

- 未开启“隔离上下文图片”的 Codex/Claude 对话继续传递每次明确附加的完整图片；
- 开启“隔离上下文图片”后，普通非游戏对话也可以批量建立图片索引、联系表和结构化摘要，不需要地图或角色编辑器；
- 图片隔离只改变匹配 Thread 的图片交付策略，不改变模型、推理强度、工具权限、画质或服务器并发；
- 同一图片按 SHA-256 去重，后续优先使用当前对话的分析摘要和文件引用；需要细节时才重新发送原图；
- 项目资源不会因为出现在工具箱、编辑器或候选列表中而自动进入对话；只有用户附件或 AI 明确读取的资源才可交付；
- 用户显式要求重新读取原图时可以再次发送完整内容，并在界面显示本回合实际交付方式；
- 普通对话不会因为打开游戏工具、地图编辑器或角色动作编辑器而自动获得写入权限。

## 8. 项目工作区

### 8.1 打开项目

主站以当前 WFL 工程真实路径为安全根。打开地图工作区时：

1. 查找用户明确选择的 `.tiled-project`；
2. 若没有该文件，仍可把 WFL 工程目录作为临时 Tiled 项目浏览；
3. 不自动创建或改写 `.tiled-project`，只有用户在新建/项目设置中确认后才写入；
4. 按 `.tiled-project` 声明的 folders 建立受限资源索引；
5. 分页返回地图、World、瓦片集、模板、图片、音频和 HTML；
6. 忽略 `.git`、运行时私有目录、符号链接逃逸和无权限路径。

### 8.2 项目树

- 支持目录展开、自然排序、类型筛选、名称搜索、刷新和最近使用；
- `.tmj` 双击打开地图标签；
- `.world` 双击打开 World 标签；
- `.tsj` 双击进入瓦片集编辑器；
- 图片点击预览，拖入画布建立图片层或瓦片对象；
- 对象模板拖入对象层建立实例；
- 多选图片拖入画布时，创建多个同原点图片层并保持选择顺序；
- 文件树只展示工程资源，不把读取权限扩大到工程外。

### 8.3 新建地图

新建按钮打开短流程向导：

- 名称和工程相对保存路径；
- 正交、等距、交错、六边形或 oblique；
- 固定尺寸或无限地图；
- 地图宽高、tilewidth、tileheight；
- stagger axis/index、hex side length 或 oblique skew 等方向专用字段；
- 背景色、render order 和初始图层名称；
- 可选外部 `.tsj`；
- Tiled 兼容版本目标。

确认前显示将创建的文件和引用，不覆盖已有路径。创建 `.tmj` 使用版本校验和原子写入，成功后在新标签
打开；失败不留下半个地图文件。

### 8.4 地图标签与恢复

- 每个地图标签拥有独立 map session、editorInstance、撤销栈和版本；
- 关闭脏标签必须选择保存、放弃或取消；
- 浏览器刷新后通过用户级 WFL 会话状态恢复标签列表和视图位置，但不恢复已撤销的安全租约；
- 外部文件变化显示明确冲突，不静默覆盖当前内存；
- 同一地图多窗口依然通过 SHA-256 产生正常 `409`，不合并撤销历史。

## 9. World 与多地图

### 9.1 `.world` 支持

- 读取、创建和无损保存标准 JSON `.world`；
- 支持显式 maps 列表、像素位置、地图尺寸和 patterns；
- 支持 `onlyShowAdjacentMaps`；
- World 视图显示多张地图，点击地图切换当前编辑文档但保持世界视口位置；
- World 工具允许添加、移除和拖动地图，方向键微调；
- World 属性、地图位置和地图内容分别保存，不能把移动 World 地图误写进 `.tmj`。

### 9.2 内存边界

- 默认只完整解析当前地图；邻图先加载边界和低成本预览；
- `onlyShowAdjacentMaps` 为真时只加载直接邻居；
- 资源纹理按内容哈希和权限作用域复用，标签关闭或地图离开邻域后释放引用；
- 不依据机器状态自动改变邻图数量，加载范围由文件和管理员/用户明确设置决定。

## 10. 图层与渲染一致性

### 10.1 图层树

- 支持拖动排序、拖入/拖出分组、复制、删除、重命名、锁定和可见性；
- 支持多选图层、批量移动、对齐、分布、锁定和可见性；
- 支持“单独显示”作为临时视图状态，不把其他图层永久改成隐藏；
- 图层和组的变更均进入结构化撤销栈；
- 组的可见性、透明度、偏移、色调、视差和混合模式按 Tiled 继承规则作用于子层。

### 10.2 Tiled 显示语义

必须补齐：

- map background color；
- orthogonal `renderorder`；
- layer/object opacity；
- `tintcolor`；
- `parallaxx/parallaxy` 与 map parallax origin；
- Tiled 1.12 `mode` 的 Normal、Add、Multiply、Screen、Overlay、Darken、Lighten、Color Dodge、
  Color Burn、Hard Light、Soft Light、Difference 和 Exclusion；
- image layer `repeatx/repeaty`；
- image layer `transparentcolor`；
- tile object alignment、tile offset、tile render size 和 fill mode；
- text object 的完整字体、对齐、换行、粗体、斜体、下划线和删除线语义；
- capsule 和 object opacity。

不支持的显示语义必须给出明确警告并继续保留数据；不能默默按另一种效果显示后让用户误判导出。

## 11. 图片图层、辅助线、裁剪与扩图

### 11.1 图片层直接操作

- 点击图片可命中并选中所属图片层；
- 拖动写入 Tiled 兼容的图层偏移；
- 方向键逐像素移动，Shift 使用用户明确设置的大步长；
- 支持网格、瓦片边界、地图边界、其他图片边缘/中心和辅助线吸附；
- 属性面板同步显示精确 X/Y、图片实际尺寸、透明度、重复、视差、色调和混合模式；
- 图层锁定后画布不能拖动，但仍可选择并解锁；
- 多选图片层可以对齐和分布。

Tiled 图片层原生不支持自由缩放和旋转。WFL 必须提供两个明确选择：

- “转换为瓦片对象”，使用 Tiled 原生对象缩放/旋转；
- “生成处理后图片”，把缩放/旋转烘焙为新的独立图片，再更新图片层引用。

不得把私有 `scale`/`rotation` 字段偷偷写进 image layer。

### 11.2 标尺与辅助线

- 画布顶部和左侧提供可缩放标尺；
- 从标尺拖出水平/垂直辅助线；
- 辅助线支持像素或瓦片单位、精确数值、锁定、隐藏和删除；
- 临时辅助线默认属于窗口视图状态，不污染 `.tmj`；
- 用户明确选择“保存为工程辅助线”时，使用不影响运行时的 Tiled custom properties，并保持可删除；
- 手机通过边缘手柄和数值面板操作辅助线，不依赖精细鼠标命中。

### 11.3 统一图片边界工具

裁剪和扩图使用同一可视边界工具：

1. 选择图片层或显式地图选区；
2. 显示原图边界和目标边界；
3. 边界向内表示裁剪，向外表示扩图；
4. 四条边可拖动，也可输入精确值；
5. 单位可选像素或瓦片，且与辅助线吸附；
6. 扩图区使用清楚的半透明覆盖，原图核心区域保持可见；
7. 提交前显示源图尺寸、逻辑目标尺寸、供应商画布、对齐策略和预期后处理；
8. 生成多个候选，支持并排/滑动对比和接缝放大检查；
9. 用户选择候选后，明确选择替换当前图层或加入新图层；
10. 应用进入撤销栈，地图仍需手动保存。

### 11.4 文件和质量语义

- 原始图片永不覆盖；裁剪、缩放、旋转、编辑和扩图生成新文件；
- 输出路径默认位于工程内 `assets/generated/`，用户可在允许目录中修改；
- 文件名包含稳定操作标识或内容哈希，重复提交幂等；
- 目标尺寸与实际输出尺寸不一致时拒绝应用；
- `preserveSource=exact` 保证原图像素恢复，`seamless` 允许明确的 blend margin；
- strict mask 模式恢复蒙版外像素，soft 模式必须在结果中标注；
- 供应商不支持目标尺寸时在任务创建前明确提示，不自动换尺寸、模型、画质或渲染策略；
- 需要 pad/crop 或 rescale/crop 时必须由用户选择，并把完整后处理记录保存在任务结果中；
- 撤销地图引用不会自动删除生成文件，避免其他地图引用丢失；清理未引用资源是独立显式操作。

### 11.5 编辑器内置图片与贴图生成

编辑器工具栏提供明确的图片工具入口，并用“生成 / 编辑 / 扩图”分段切换。它是可直接操作的工作面板，
不要求用户先去对话中编写命令。

- 生成允许选择植物/道具、地块纹理、完整背景、装饰层和自定义五类用途；预设只填写建议参数，用户仍可
  查看并修改模型、尺寸、质量、数量、透明背景、输出目录和文件名；
- 编辑必须由用户显式选择工程图片、当前图片层或画布选区；扩图必须同时显示源边界和目标边界；
- 生成植物和道具时支持供应商原生透明背景，并校验实际 alpha；供应商不支持时禁用该选项，不能用白底
  结果冒充透明 PNG；
- 生成地块时可明确开启水平/垂直无缝平铺，目标尺寸必须与 tile size 和切分网格一致，并提供边缘接缝
  像素检查；
- 结果可以发布为普通图片层、image collection TSJ 的新 tile、atlas 候选或组合素材依赖；生成 `PNG + TSJ`
  时使用同一多文件事务；
- 每个候选先停留在任务候选区，显示透明度、实际尺寸、文件大小、内容哈希和放大预览；未发布候选不写入
  地图、瓦片集或正式素材库；
- 能力按供应商、模型和 `generate/edit/outpaint` 分别声明与探测；不支持的操作、蒙版、透明背景、尺寸、
  多图输入或流式局部结果不能出现在可用控件中；
- 成功结果记录 provider、operation、model、`sourceConsumed`、输入图片用量、请求尺寸、供应商画布、实际
  尺寸、后处理、SHA-256、request ID 和 job ID；调用方可以据此确认是否真的使用了源图；
- MCP 工具目录必须在能力变化后可靠刷新；不能刷新时静态暴露稳定工具并返回明确的
  `IMAGE_OPERATION_UNAVAILABLE`，绝不能把编辑或扩图静默降级成普通生成；
- 只有工具 schema 和事件通道真正支持局部图片时才声明 streaming；局部结果只用于预览，不自动发布；
- AI 可以提交图片任务提案，但用户必须确认完整参数和可能用量；任务结果不自动附加到对话上下文。

## 12. 瓦片地图日常编辑

### 12.1 Stamp 和选择

- 单瓦片和多瓦片 stamp；
- 从瓦片集选区建立 stamp，从地图右键/取样工具捕获 stamp；
- 直线、矩形、椭圆和中心扩展绘制；
- stamp 水平/垂直翻转及旋转；
- 随机模式和 tile probability；
- 命名 stamp、最近使用、收藏及快捷槽位；
- 矩形选择、魔棒、选择同类瓦片；
- 替换、追加、减去和交集选择模式；
- 选区移动、复制、粘贴、翻转、旋转、删除和跨层明确粘贴；
- 形状填充、选区填充和可取消的大范围 flood fill。

### 12.2 Terrain/Wang Set

- 读取和显示 corner、edge、mixed Terrain Set；
- Terrain Brush 自动选择边缘、角落和邻接瓦片；
- Terrain Fill 与随机变体遵循 tile/terrain probability；
- 支持 tileset transformations 中允许的翻转和旋转；
- 修改时只改变用户选择的图层及必要邻格；
- 所有自动改动作为一个可预览、可撤销操作；
- 大范围 Terrain 计算放在浏览器 Worker，不能阻塞主 UI，也不能进入主站 Node 堆。

### 12.3 无限地图

- 画笔越界时按原 chunk 大小创建 chunk；
- 擦除空 chunk 后可回收，但不改变其他 chunk 的编码；
- fill 只作用于当前图层已有边界，除非用户明确指定选区；
- 固定/无限地图转换先预览新边界，确认后作为完整文档操作；
- 不因为视口裁剪而丢弃未显示 chunk。

## 13. 对象、碰撞和游戏语义

### 13.1 对象工具

必须支持创建和编辑：

- 矩形；
- 点；
- 椭圆；
- Tiled 1.12 胶囊；
- 多边形；
- 折线；
- 瓦片对象；
- 文字对象；
- 对象模板实例。

### 13.2 变换和选择

- 单选和多选；
- 拖动、方向键微调、缩放、旋转和锚点；
- 顶点新增、删除、移动和折线延伸；
- 网格、像素、辅助线、对象边缘和对象中心吸附；
- 对齐、分布、复制、粘贴、前移、后移；
- tile object 使用 TSJ object alignment 和 tile offset；
- 所有变换显示精确数值并进入撤销栈。

### 13.3 碰撞、出生点和传送点

- 碰撞允许矩形、椭圆、胶囊、多边形和折线；
- tile collision 与地图对象碰撞可以分别显示和隐藏；
- 出生点使用 point 对象和项目 Class；
- 传送点使用对象引用/文件属性连接目标地图和目标出生点；
- World 视图可画出跨地图传送连接并检查失效引用；
- 编辑器只提供通用 Tiled 数据，不硬编码某个游戏引擎的运行时类名；
- 工程模板可以定义默认 SpawnPoint、Portal、Collision 等 Class。

## 14. 瓦片集编辑器

### 14.1 创建与导入

- 默认创建外部 `.tsj`；
- 支持单图 atlas 和 image collection；
- atlas 设置 tilewidth、tileheight、margin、spacing、columns 和透明色；
- image collection 支持批量选择独立 PNG/WebP 并分配稳定 tile ID；
- 解码图片尺寸与 TSJ 声明不一致时明确失败，不截短或猜测；
- 导入已有 TSJ 时继续校验 GID 范围和全部图片依赖。

### 14.2 每瓦片数据

- 名称/Class、自定义属性、probability；
- tile collision object group；
- 线性循环动画、帧顺序和帧时长；
- Terrain/Wang 标记；
- image collection 的单瓦片图片替换；
- tile object alignment、tile offset、grid orientation 和 transformations；
- 多瓦片批量属性和碰撞操作。

### 14.3 GID 稳定性

- 编辑 TSJ 不改变地图里的 firstgid；
- 删除 tile 不重排后续 tile ID；
- 新瓦片只使用未冲突的稳定本地 ID；
- 跨工程复制 TSJ 时先复制全部依赖，再在目标地图分配新的 firstgid；
- 保存前检查最高 GID 不进入 Tiled 翻转标志位。

## 15. 自定义类型与对象模板

### 15.1 `.tiled-project` 类型

- 读取和编辑 Class、Enum 及 Tiled 1.12 List 属性；
- Class 支持嵌套 Class 成员和默认值；
- Enum 支持字符串/整数保存及多选；
- 属性编辑器按 bool、color、file、float、int、object、string、class、enum、list 提供对应控件；
- file 只能选择工程内允许资源；
- object 引用提供跳转和失效检查；
- 类型修改不自动重写全部地图，先显示受影响文件并要求用户确认迁移。

### 15.2 对象模板

- 从对象保存 Tiled 模板；
- 从项目树拖入模板建立实例；
- 正确合并模板值和实例覆盖值；
- 模板变化时提示刷新受影响地图，不覆盖实例明确覆盖的字段；
- 支持解除模板绑定；
- 模板引用继续使用工程相对路径。

### 15.3 多图层组合素材

Tiled 对象模板只覆盖单个对象，不能原生表示多图层组合。WFL 使用标准文件组合实现：

- 组合素材源是一个小型 `.tmj`；
- 用户可把当前选中的图层/分组保存为模板地图；
- 导入时把图层复制进当前地图的一个 group；
- 重新分配 layer ID、object ID 和目标地图 firstgid；
- 复制或复用工程内图片、TSJ 和模板引用；
- 跨工程导入必须把依赖复制到目标工程并重写相对路径；
- 导入是一次可撤销、可回滚的事务，不在目标 `.tmj` 写入私有实时链接。

## 16. 素材库

### 16.1 分类

```text
工程素材
├── 图片
├── 瓦片集
├── 地图
├── 对象模板
├── 组合素材
├── 音频
└── 游戏入口
```

### 16.2 能力

- 缩略图、名称搜索、目录筛选、最近使用和用户收藏；
- 图片实际尺寸、格式、透明度、文件大小和 SHA-256；
- TSJ 的 tile size、类型、tile count、Terrain/动画/碰撞摘要；
- TMJ 的方向、尺寸、图层数、依赖和预览；
- 依赖关系查看、缺失资源诊断和重新链接；
- 拖入地图时根据类型创建图片层、瓦片集引用、对象实例或组合分组；
- 素材候选和已发布素材分开显示；
- AI 生成结果只有用户明确发布后才进入工程素材；
- 素材出现在界面中不等于进入对话上下文。

项目共享标签优先使用 Tiled Class/custom properties；仅用于界面排序的收藏、最近使用和面板状态保存在
用户私有状态中，不要求游戏运行时解析 WFL 元数据。

## 17. Automapping

Automapping 排在核心编辑器和 Terrain 之后实施：

- 支持项目 `.tiled-project` 指定规则文件；
- 支持地图目录旁的 `rules.txt` 覆盖；
- 读取标准规则 `.tmj` 的 input/inputnot/output 和规则属性；
- 支持手动 AutoMap 和明确开启的 AutoMap While Drawing；
- 规则结果先形成预览和一个撤销项；
- 随机输出使用记录在操作中的 seed，保证撤销/重做及测试可重复；
- 大规则在浏览器 Worker 中运行；
- 不执行脚本，不允许规则访问工程外文件；
- 对 Tiled 官方已注明受限的六边形 Automapping 给出明确提示，不伪装成完整支持。

## 18. AI 协作工作区

### 18.1 右侧同线程对话

- 默认连接从主界面打开地图时携带的当前 Thread；
- 顶部清楚显示工程、Thread 和是否拥有地图工具权限；
- 用户可以切换同工程 Thread；
- 对话显示图片缩略图不代表向模型重新发送图片；
- 消息发送、审批、停止、追加指令和恢复沿用主界面权威协议；
- 不建立第二份 Conversation Store。

### 18.2 地图 AI 工具

在现有 `get_map_context` 和 `propose_tiled_patch` 基础上，按阶段增加有界工具：

- `list_project_maps`：返回地图摘要，不返回文件全文；
- `get_map_context`：返回当前地图、版本、方向、尺寸和图层摘要；
- `list_map_layers`：分页返回图层 ID、类型、层级和基础属性；
- `read_map_region`：只读明确图层和有限矩形区域；
- `list_map_assets`：分页返回已授权素材元数据；
- `propose_tiled_patch`：提交结构化提案，不直接写文件；
- `request_map_preview`：创建受限临时预览任务，不把截图自动加入对话；
- `request_map_image_job`：创建用户参数完整的图片任务候选，不自动应用。

所有工具都必须重新验证用户、Thread cwd、工程、地图会话、版本、editorState、窗口租约和 allowedOps。
工具描述保持短小明确，让 AI 通过 schema 理解工具；不把地图全文塞进系统提示词。能力变化使用可靠的
工具目录刷新或稳定静态 schema 加显式 unavailable 错误，不能重现图片工具目录过期问题。

### 18.3 提案体验

- 新提案实时进入右侧“AI 修改”，不要求手动刷新；
- 画布以 ghost overlay 显示受影响瓦片、对象、图层和资源；
- 列出操作数量、影响区域、资源依赖和冲突；
- 用户可以整批接受、整批拒绝或选择允许拆分的独立操作；
- 应用前再次校验地图版本、editorState 和原始提案哈希；
- 应用只改变当前窗口内存，保存仍由用户触发；
- 线程切换、地图保存、窗口关闭或本地状态变化使旧提案明确过期。

### 18.4 Codex 与 Claude 范围

- 当前地图 MCP 首先继续服务 Codex 原生 Thread；
- Claude 右侧对话可以复用同工程会话显示与图片隔离规则；
- Claude 获得地图写提案能力前，必须建立等价的工具身份、Thread 绑定和 fail-closed 租约，不能通过
  把地图全文粘进提示词临时绕过；
- 任一提供方的普通非游戏对话不受地图图片隔离影响。

### 18.5 两种协作模式的责任边界

地图 AI 不应只有“能用/不能用”两个状态，而应把责任边界做成用户能理解的协作等级：

| 协作等级 | AI 可以做什么 | 是否写入工程 | 用户责任 |
| --- | --- | --- | --- |
| 只读检查 | 读取工程清单、地图摘要、有限区域并给出诊断 | 否 | 查看结果 |
| 编辑器协作 | 生成结构化提案、ghost preview、差异和修复计划 | 用户点击应用后进入窗口内存 | 审批每个批次并决定保存 |
| AI 托管 | 在授权范围内直接应用已校验补丁、保存和生成预览 | 是，使用原子事务 | 预先决定范围、操作类别和停止条件 |

“AI 托管”不是无限权限。它是用户提前签署的一份短期协作合同，至少包含：

- 当前用户、当前 Thread、工程和地图范围；
- 允许读取、提案、直接修改、素材发布、渲染、恢复等操作类别；
- 受保护的图层、对象、区域和文件；
- 最大单批变更数量、最大影响区域和最大文件数量；
- 授权有效期、任务超时、暂停策略和完成条件；
- 地图专用批准策略：`每条询问`、`AI 审查`或`完全授权`。

这些限制必须由用户明确选择或确认，不能由系统根据 CPU、内存、地图大小或 AI 判断自动调整。

地图批准策略借鉴对话中的批准/复核设置，但不直接复用对话的 `approval_policy` 或 `sandbox_mode`。对话审批控制
Codex 的命令、文件和权限请求；地图批准策略只控制结构化地图补丁和地图事务。两者必须在界面上分别显示，不能因为
用户把对话设置为“完全授权”就自动获得地图写入权限。

参考关系如下，实际实现仍保存两套独立字段：

| 对话层参考组合 | 地图层显示 | 说明 |
| --- | --- | --- |
| `approval_policy=on-request` + `approvals_reviewer=user` | `每条询问` | 对话和地图都倾向人工逐项确认，但地图仍有自己的范围和硬门槛 |
| `approval_policy=on-request` + `approvals_reviewer=auto_review` | `AI 审查` | 只作为界面理解上的参考；地图服务端仍按固定风险规则和授权合同执行 |
| `approval_policy=never` | `完全授权`的参考入口 | 仅表示用户偏好少打断；不能自动创建地图授权，也不取消路径、版本、格式和运行时拦截 |

`guardian_subagent` 等对话复核方式也不能替代地图批准策略。以后如果地图增加独立审查器，必须单独记录审查器身份、
版本、审查摘要和最终责任人。

| 地图批准策略 | 行为 | 人工介入点 | 适合场景 |
| --- | --- | --- | --- |
| 每条询问 `ask_each` | 每一个会改变地图、TSJ、资源引用或版本的操作单独生成批准卡；未批准前不进入写入 | 每条操作都由用户批准、拒绝或修改范围 | 新手、关键地图、首次使用 |
| AI 审查 `ai_review` | 服务端先按固定规则生成风险结果；低风险操作可按批次执行，中/高风险按规则暂停并询问用户，AI 只负责解释 | 风险升级、保护区冲突、跨文件、运行时语义变化和版本冲突 | 日常制作，兼顾连续性与安全 |
| 完全授权 `full_authorization` | 用户对已选范围和操作类别预先授权，允许托管任务连续执行，不逐条弹窗 | 仅安全硬门槛、格式错误、路径越界、权限失效、版本冲突和运行时不兼容强制拦截 | 熟悉流程的批量制作 |

“完全授权”只表示免除人工逐条批准，不表示允许越过安全硬门槛，也不允许访问授权范围外的工程、地图或文件。

### 18.6 人工协同优化：先定合同，再连续执行

为了避免 AI 每修改一个对象就打断用户，同时避免 AI 无边界乱改，采用“任务合同 + 批次检查点”：

1. 用户用自然语言描述目标，例如“把东侧出口接到 forest，并补齐碰撞”。
2. AI 先返回一份紧凑计划：目标地图、预计文件、预计操作、不会修改的内容、验证方式和完成条件。
3. 用户选择“只生成提案”或“进入托管”，并选择地图批准策略：`每条询问`、`AI 审查`或`完全授权`；托管模式下只有
   点击“授权执行”才进入写入阶段。
4. AI 将任务拆为可恢复批次，例如“结构调整”“对象和碰撞”“资源引用”“预览校验”。
5. 每个批次内部保持原子性，批次之间显示一次短摘要，而不是逐个操作弹窗。
6. 根据批准策略处理批次：`每条询问`逐操作暂停，`AI 审查`按风险和规则暂停，`完全授权`不因风险等级弹窗，
   但所有安全硬门槛仍然强制停止。
7. 完成后返回文件差异、版本号、验证结果、预览和恢复入口。

风险分类仍按语义划分，而不是按操作数量或设备状态猜测：

- 低风险：对象位置、普通属性、非锁定装饰层内的小范围瓦片修改；
- 中风险：碰撞、出生点、传送点、交互对象、外部 TSJ 引用和大范围填充；
- 高风险：删除或重命名图层、改变地图尺寸/方向、替换共享瓦片集、跨多个地图的事务、发布新资源。

三档策略的具体规则：

- `每条询问`：低、中、高风险以及资源发布都逐条询问；服务端先把一个补丁拆成最小可审查操作单元，AI 不能把多项
  操作塞进一个大补丁来绕过询问；读取、纯校验和不产生文件变化的预览不需要询问；
- `AI 审查`：服务端必须在批次提交前按固定规则生成机器可读的风险分类、影响文件、影响区域、保护区检查、回滚点和验证计划；
  AI 可以补充自然语言说明，但不能改变风险等级。低风险可连续执行，中风险默认按批次询问，高风险必须逐条询问；
- `完全授权`：在用户已经明确批准的地图范围和操作类别内连续执行，不再按风险弹窗；遇到安全硬门槛时直接失败或暂停，
  不能要求 AI 自行选择绕过方式。

每一张批准卡必须显示：操作类型、目标地图/文件、影响图层和区域、预计变更数量、风险原因、基础版本、回滚点、验证结果、
是否会生成或发布图片，以及“只批准这一项/拒绝/改为仅提案/切换批准策略”按钮。只有用户另外点击“本任务同类操作都批准”时，
才可以扩大到当前任务的同类操作；这不能改变地图范围、操作白名单或安全硬门槛。用户可以把当前任务切换到更严格策略；
运行中的批次策略快照不被悄悄放宽，放宽只对新批次生效。

### 18.7 人工的保护区、所有权和接管

协同的核心不是让 AI 猜测哪些地方不能动，而是让用户可以明确声明：

- 锁定图层：AI 可以读取但不能修改；
- 锁定对象：例如出生点、主任务 NPC、关键传送点；
- 锁定区域：以地图坐标矩形或多边形保存，不依赖图片像素；
- 人工所有区、AI 所有区和共享区：作为协同标记，不改变 Tiled 运行语义；
- 保护文件：例如 `collision.tmj`、共享 `terrain.tsj` 或原始美术源文件；
- 允许 AI 修改的目标清单：明确到图层、对象类型或资源目录。

保护信息保存为 WFL 用户/工程私有状态，不能写入会改变游戏运行语义的私有必需 Tiled 字段。AI 每次提交前重新检查
保护规则；保护规则变化只影响新批次，已进入原子写入的批次不被中途改写。

用户可以点击“暂停 AI、保留已完成批次”，随后人工编辑。点击“接管任务”后：

- 当前未提交批次立即取消；
- 已完成批次保留在历史中；
- 新人工版本成为后续 AI 任务的唯一基础版本；
- 原 Thread 仍可查看结果，但不能继续写入，除非用户重新授权。

### 18.8 选择、指向和反馈不依赖图片上下文

人工与 AI 协作需要一个低 Token 的指向协议：

- 用户在画布框选区域、点击对象或选择图层后，发送的是 `mapSelection` 引用：地图路径、图层 ID、对象 ID、坐标范围和版本哈希；
- 不把当前画布截图自动发送给 AI；
- AI 可以返回结构化关注区域、对象列表、诊断标记和建议视口；
- 画布用 ghost overlay、差异热区、对象标签和警告图标显示结果；
- 标记和评论存放在独立的用户协同状态中，不混入 `.tmj`，也不会被游戏运行时读取；
- 用户明确要求“看这张图”时才读取受限缩略图，且按内容哈希去重。

这样用户可以用鼠标“指给 AI 看”，AI 也能用坐标和对象 ID “指回去”，不需要在连续对话中重复上传整张地图或全部素材。

### 18.9 任务、对话和人工接管的状态机

托管任务使用持久状态，而不是只依赖浏览器页面：

```text
draft
  -> awaiting_authorization
  -> planning
  -> awaiting_approval（仅每条询问或 AI 审查命中规则时）
  -> queued
  -> running_batch
  -> validating
  -> committed
  -> previewing
  -> completed
```

任一阶段可以进入：

```text
paused / cancelled / conflict / validation_failed / failed / restored
```

任务状态必须显示“下一步是谁负责”：

- `awaiting_authorization`：用户授权；
- `awaiting_approval`：用户查看操作卡，批准、拒绝、改为提案或切换到更严格策略；
- `conflict`：用户刷新地图或接管；
- `validation_failed`：用户修复地图/工程约束；
- `completed`：用户查看摘要或打开编辑器；
- `failed`：系统保留错误和恢复入口。

批准策略保存在任务合同和每个批次的策略快照中。用户可以把新批次切换到更严格的策略；“完全授权”不能被 AI 自行
切换，放宽策略必须重新由用户点击授权。紧急暂停和撤销可以立即阻止后续批次，但不会截断已经进入原子提交阶段的批次。

切换同工程的另一个 Thread 时，旧 Thread 的写权限不自动转移。用户可以显式“转交任务”，转交会撤销旧 Thread
的写租约并生成新的接管记录。其他同工程对话可以只读查看任务摘要，但不能暗中修改同一地图。

### 18.10 冲突策略：宁可重规划，不做静默合并

人工在 AI 思考期间修改地图时，写入前必须重新比较基础哈希和保护区域：

- 默认严格冲突：基础版本变化就暂停，不覆盖人工修改；
- 界面显示人工变化涉及的图层、对象和区域；
- AI 可以读取新版本的紧凑差异并生成新的补丁，但必须产生新的检查点；
- 第一阶段不做静默三方合并；
- 后续如果实现“非重叠区域重放”，也必须是用户事先手动开启的协同策略，并在应用前显示重放清单；
- 任何包含碰撞、出生点、传送点或共享瓦片集的冲突都必须人工确认。

编辑器打开且存在未保存内容时，外部托管提交只显示“磁盘有新版本”，不自动覆盖本地脏状态。用户可以选择保存本地、
加载远程、查看差异或放弃本地编辑。

### 18.11 AI 工具协议和上下文控制

托管模式增加稳定、短小、结构化的工具集合：

- `inspect_project`：读取工程类型、运行时能力、地图列表和验证入口；
- `get_map_context`：读取地图结构摘要、版本和警告；
- `read_map_region`：按图层和坐标读取有限区域；
- `apply_tiled_patch`：先 dry-run，随后在已有 `direct_apply` 权限下原子提交；
- `validate_map`：运行 Tiled、资源引用和项目运行时校验；
- `request_map_preview`：创建独立预览任务；
- `list_map_revisions` / `restore_map_revision`：查看和恢复历史版本。

工具目录始终可发现。未授权、过期、越界和能力不支持都返回稳定错误码，不通过隐藏工具或把失败伪装成普通文件操作来引导 AI。
工具结果优先返回摘要、下一步和版本凭据，禁止默认返回整份 JSON、图片字节或完整渲染图。

AI 的推荐调用顺序固定为：

```text
inspect_project
  -> get_map_context
  -> read_map_region（仅在需要时）
  -> apply_tiled_patch(dryRun=true)
  -> validate_map
  -> apply_tiled_patch(direct_apply=true)
  -> request_map_preview（用户要求或授权包含预览时）
```

如果某一步失败，工具返回可操作的下一步，不让 AI 自行改用绝对路径、Shell 或整文件覆盖作为“备用方案”。

### 18.12 wflgame 运行时能力协同

`wflgame` 当前可能仍使用 `backgroundAsset` 和对象层，而不是完整瓦片/图像层运行时。托管工具必须先读取工程能力
清单；如果运行时不支持 `tilelayer`、`imagelayer` 或外部 TSJ，AI 只能修改已声明支持的结构，并返回
`RUNTIME_LAYER_UNSUPPORTED`，不能生成一个 Tiled 看似正确但游戏无法加载的地图。

当前仓库的只读探测结果固定为 `wflgame-runtime-v1`：Phaser 运行时可解析并渲染
`objectgroup`、`imagelayer` 和分组图层；`tilelayer` 虽可被协议解析，但没有检测到游戏渲染路径，托管 AI 不得写入瓦片；
没有检测到外部 `.tsj`、`.world` 或模板加载器。`scripts/check-tiled-maps.mjs` 作为项目校验入口，业务层和属性摘要也会随能力
返回，但不把绝对路径、源代码或图片字节暴露给 AI。该能力摘要在 `inspect_project` / `get_map_context` 返回，并在提案、独立
Worker 和最终保存前重复校验，避免能力在长任务期间被绕过。

地图结构迁移和 Phaser/游戏代码迁移必须分成两个可审查任务：地图工具负责 Tiled 数据，普通工程开发工具负责运行时代码，
两者通过显式迁移计划和验证命令衔接。AI 不得把“地图视觉预览正常”当成“游戏运行时已兼容”。

### 18.13 固定规则审查引擎（MVP）

阶段 11 的 `AI 审查`不启动嵌套 Codex 对话、不让模型自评权限，也不根据 CPU、内存、设备、队列长度或模型意见动态
改变风险等级。服务端使用版本化、可测试的 `map-risk-v1` 规则集，规则结果、命中原因和输入摘要写入任务审计。

当前已完成一个未接入写入路径的稳定原型：`lib/map-ai-risk.mjs` 提供纯函数风险判定和三档策略决定，
`lib/map-ai-approval-policy.mjs` 只负责把对话批准设置转换为推荐值并生成需要用户确认的策略快照；两者均不读文件、
不调用模型、不修改现有 MCP 和地图文件。对应聚焦夹具位于 `test/map-ai-risk.test.mjs` 和
`test/map-ai-approval-policy.test.mjs`，接入主站前必须继续通过现有地图 AI 回归。

固定分类如下：

| 等级 | 固定判定条件（任一命中即至少达到该等级） | 典型操作 |
| --- | --- | --- |
| 只读 | 不产生工程文件变化 | 读取、校验、结构摘要、有限区域查询、临时预览 |
| 低风险 | 单张地图、一个未锁定装饰层；不改变图层结构、运行时关键对象或外部依赖；最多 256 个瓦片格或 16 个普通对象操作 | 小范围装饰填充、普通对象移动、普通属性更新 |
| 中风险 | 257–4096 个瓦片格、17–64 个普通对象操作，或触及碰撞/出生点/传送点/交互对象/大范围填充/单个外部 TSJ 引用 | 碰撞修补、出口连接、较大区域地形修改、增加一个受控资源引用 |
| 高风险 | 超过 4096 个瓦片格或 64 个对象；新建/删除/重命名/重排图层；改变地图尺寸或方向；替换共享 TSJ；跨地图事务；发布新图片或删除源文件 | 结构迁移、共享资源替换、跨地图连接、素材发布 |

以下条件不是风险等级，而是所有模式都必须硬拒绝或暂停：

- 用户、Thread、工程、地图范围或操作白名单不匹配；
- 保护图层、对象、区域或文件被触碰；
- 基础版本哈希变化、重复提交无法通过幂等校验或事务状态不确定；
- 绝对路径、符号链接越界、URL、Base64、非法外部引用或文件类型不允许；
- TMJ/TSJ 解析、未知字段保留、运行时能力或项目验证失败；
- 暂存、fsync、原子替换、多文件提交或恢复记录失败。

三档策略套用同一份 `map-risk-v1`：

- `ask_each`：低、中、高风险每个最小操作单元都询问；只读不询问；
- `ai_review`：低风险按批次自动通过，中风险按批次询问，高风险逐条询问；服务端规则决定结果，AI 只生成说明；
- `full_authorization`：用户已明确授权的风险等级都可连续执行，但硬拒绝条件始终生效。

规则集升级必须使用新版本号、重新运行夹具和安全测试；旧任务继续使用创建时的规则快照。管理员不能在线修改规则阈值，
如需调整必须通过版本发布和回归验证，避免同一任务前后风险判定不一致。

### 18.14 持久托管任务状态层（稳定性基础）

当前已增加 `lib/map-ai-managed-task-store.mjs`，它是一个不持有地图文件句柄、也不启动执行器的持久状态机。任务合同会原子
写入独立的 `map-ai-managed-tasks.json`，保存工程/地图/Thread 范围、操作白名单、保护目标、批准策略快照、规则版本、计划哈希、
配置快照、有效期和有限事件/批次检查点；公共快照不返回计划正文或服务端绝对路径。创建使用客户端幂等键，同一幂等键提交不同计划
会拒绝。

状态机支持排队、运行、等待批准、暂停、恢复、取消、人工接管、失败和版本冲突。每个批次必须带基础哈希、目标哈希和风险收据；
同一批次只允许按 `started -> awaiting_approval -> committed/failed` 单向推进，重复请求幂等，基础版本不匹配时进入冲突终态。服务重启时
所有活动任务统一标记为 `interrupted`，不会自动重放；恢复必须携带任务 ID 的显式确认，以便后续执行器先重新读取当前地图并核对未知提交。

该层已经接入主站启动和用户/浏览器会话资源释放。当前同时提供独立的托管授权与只创建合同的任务入口：

- `POST/GET/DELETE /api/map-ai/managed-authorizations`：创建、查询和撤销无编辑器授权；创建时复验工程、Thread、地图基础哈希和可写权限；
- `POST/GET /api/map-ai/managed-tasks`：在授权范围内建立或查询持久任务合同；
- `POST /api/map-ai/managed-tasks/:id/action`：处理批准、拒绝、暂停、恢复、取消和人工接管。

任务合同不会绕过授权和编辑器/服务器的安全边界直接整文件覆盖；现已接入 `lib/map-ai-managed-task-executor.mjs` 作为第一版受控执行器：

- 只接受 `wfl-tiled-patch` 结构化计划，不接受整份 `.tmj`、工程绝对路径、图片字节或凭据；
- 每次执行前重新读取地图并核对托管授权、Thread、工程相对路径和基础 SHA-256；
- 复用浏览器侧的 `parseTiledAiPatch`、Tiled 编辑模型和填充预计算，先生成候选文档并重新序列化；
- 通过现有 `MapSaveSessionStore` 上传分块、子进程 Tiled 校验、目标锁、版本哈希和原子替换；
- 地图补丁的解析、预览、填充计算和候选 TMJ 生成已移入独立 `map-ai-patch-worker`；主站只负责实时授权复验、任务状态和分块原子提交。生产环境 Worker 使用 transient `systemd-run` cgroup（`MemoryMax`、`MemorySwapMax=0`、`RuntimeMaxSec`、`KillMode=control-group`、`OOMPolicy=stop`）及受限文件系统和最小环境变量；开发/测试环境可显式使用 direct 子进程。两层都保留独立 Node 堆、进程树内存预算、输出哈希校验和私有临时目录，Worker 失败不会让聊天主站进程退出；超时、取消、输出超限、候选篡改、符号链接和路径越界都会只失败当前任务并回收任务树；
- `ask_each` 的多操作计划现在按操作级检查点执行：每次只预览和提交当前操作，提交后推进任务版本和 `nextOperationIndex`，下一操作重新进入 `awaiting_approval`；拒绝或取消不会回滚已经提交的操作，也不能通过合并计划绕过逐条批准。`ai_review` 的固定规则仍按批次或操作升级，只有显式 `approve` 才继续；
- `full_authorization` 仍受硬安全门槛约束；版本冲突、授权变化、校验失败和单任务异常只影响当前任务；
- 成功后写入批次检查点和新版本，编辑器可通过任务快照和事件增量读取同步状态。
- 批准/恢复接口先持久化状态并立即返回，执行器通过受控队列在后台运行；HTTP 请求不会等待大地图解析、Tiled 校验、分块上传或原子提交。
- 检查点只保存有界差异收据（操作计数、类型统计、前 24 条摘要和截断标记）及有界校验诊断，不把完整操作列表复制进持久任务状态。
- 地图编辑器“任务”侧栏现在同时显示图片、渲染和托管地图任务；托管任务按 1.5 秒轮询并读取事件增量，显示最近风险/检查点摘要，等待批准时可批准、暂停、取消或人工接管，服务重启后的 `interrupted` 任务恢复时要求显式确认。
- 托管任务成功更新服务端版本后，干净编辑器会先撤销旧地图 AI lease 再安全刷新并保留视图状态；存在未保存编辑时只提示人工重新加载，绝不覆盖本地内容。
- 托管执行前重新解析工程真实路径并拒绝目标文件符号链接或工程外路径；任务动作、事件、检查点和版本冲突均保持用户/浏览器会话隔离。

### 18.15 无编辑器 Managed MCP 工具（已接入第一版）

编辑器协作 MCP 与无编辑器托管 MCP 是两个独立服务，分别由 `wfl_map_ai` 和
`wfl_map_ai_managed` 注入 Codex app-server。托管服务不接受 `mapSessionId`、`editorInstanceId`、lease、token、
绝对路径或图片字节；工具目录固定暴露安全工具，授权在每次调用时通过持久化授权 ID、用户、Thread、工程指纹、
地图相对路径和地图 SHA-256 重新解析。关闭地图编辑器或轮换浏览器会话不会静默撤销这种用户明确创建的托管授权，
但用户撤销授权、过期、账号停用或工程/地图版本变化会立即拒绝后续调用。

当前工具包括：`inspect_project`、`get_map_context`、`read_map_region`、`validate_map`、`request_map_preview`、
`propose_tiled_patch` 和 `apply_tiled_patch`。只读结果只返回有限元数据、图层摘要、小区域 GID 和工程相对引用，
不会把完整地图、图片字节或路径注入普通对话。`propose_tiled_patch` 只返回受限预览和风险收据；
`apply_tiled_patch` 只创建持久化托管任务，随后仍由 `map-risk-v1`、批准策略、Worker、版本复验和原子保存链执行。
托管 MCP 目录在未授权时也不变为空目录，长期 Codex 会话不会因为首次打开地图编辑器前没有授权而永久缓存“没有工具”。

服务重启后仍不自动重放；`interrupted` 任务必须带任务 ID 显式确认后恢复。当前执行器支持单地图补丁和显式覆盖全部授权地图的多地图事务；`ask_each` 对多地图计划按事务整体询问，不把事务拆成可能产生部分提交的逐地图批次。托管授权现在支持显式 Thread 转交：目标 Thread 必须重新通过工程归属校验，旧 Thread 工具范围立即失效，旧任务被取消并留下转交审计。TSJ/图片/模板/World 候选已通过显式资源补丁和依赖闭包事务发布；任务事件使用有界序号、HTTP 增量读取和断档/终态快照恢复。完整 SSE 推送仍不是当前阶段的必要条件，浏览器使用受控轮询保持主站稳定。

## 20. 服务端和 API 增量

以下为计划接口，命名可在实现时与现有路由保持一致，但权限和版本语义不得弱化。

### 20.1 项目会话

- `POST /api/map-projects/sessions`：建立当前用户/工程的项目会话，可指定 `.tiled-project`；
- `GET /api/map-projects/sessions/:id/tree`：按目录、类型和 cursor 分页列出资源；
- `GET /api/map-projects/sessions/:id/search`：有界搜索工程资源；
- `POST /api/map-projects/sessions/:id/maps`：原子创建新 `.tmj`；
- `POST /api/map-projects/sessions/:id/tilesets`：原子创建新 `.tsj`；
- `POST /api/map-projects/sessions/:id/worlds`：原子创建新 `.world`；
- `POST /api/map-projects/sessions/:id/imports`：提交多文件/组合素材导入计划；
- `DELETE /api/map-projects/sessions/:id`：撤销项目会话及其临时授权。

项目会话不能代替地图会话。打开具体 `.tmj` 后仍使用现有 map session、专用分段读取和分块原子保存。

### 20.2 多文件事务

新建组合素材、跨工程导入、生成派生图片并更新引用可能涉及多个文件，必须使用显式事务：

1. 服务器生成文件清单、目标路径、期望旧哈希和总配额；
2. 用户确认计划；
3. 每个输出写入同文件系统暂存目录；
4. 校验全部内容、Tiled 引用、哈希、权限、配额和当前版本；
5. 使用事务清单按可恢复顺序原子提交；
6. 任一提交前失败不改变工程；
7. 进程中断由恢复器根据事务状态完成回滚或收尾；恢复器按设备号/inode、候选哈希和原文件哈希逐文件复验，
   绝不盲目 `rename` 覆盖现存目标；发现外部替换、日志损坏、路径越界或缺少备份时保留现场并报告管理员；
8. 不能把部分成功伪装成完整导入。

### 20.3 事件通道

- 原生对话继续使用现有 WebSocket 事件；
- 地图提案、项目文件变化和任务状态使用带用户/窗口/会话校验的 SSE 或现有受控事件通道；
- 每条事件携带递增序号或稳定 event ID，重连后可恢复而不重复应用；
- 浏览器事件只更新显示，不能替代保存时的权威版本复验。

### 20.4 AI 托管与人工接管接口

新增接口必须与现有编辑器地图会话分离，但使用同一版本和保存服务：

- `POST /api/map-ai/managed-authorizations`：创建托管授权，绑定用户、Thread、工程、地图范围、操作范围、保护规则、
  `approvalPolicy`（`ask_each`/`ai_review`/`full_authorization`）和有效期；
- `GET /api/map-ai/managed-authorizations/:id`：返回脱敏的授权状态、剩余时间、当前任务和可执行操作；
- `DELETE /api/map-ai/managed-authorizations/:id`：立即撤销未提交的托管写权限；
- `POST /api/map-ai/tasks`：创建可暂停、可恢复的托管任务，保存任务合同、批准策略和配置快照；
- `POST /api/map-ai/tasks/:id/approval`：处理当前批准卡，支持 `approve`、`reject`、`proposal_only`、`tighten_policy`；
- `POST /api/map-ai/tasks/:id/pause`：在当前批次结束后暂停，不截断原子提交；
- `POST /api/map-ai/tasks/:id/takeover`：撤销 AI 写租约，把后续控制权交给当前用户或新 Thread；
- `GET /api/map-ai/tasks/:id/diff`：返回结构化差异、影响区域和验证摘要，不默认返回图片字节；
- `GET /api/map-ai/tasks/:id/events`：按 event ID 恢复任务进度和人工检查点；
- `POST /api/map-ai/tasks/:id/restore`：以新版本恢复指定任务前的快照；
- `POST /api/map-ai/revisions/:id/reapply`：在用户确认新基础版本后重新生成待应用补丁，不自动重放。

项目级事务恢复已接入主站主启动路径（不在 4321 救援模式运行）：启动后异步扫描当前主站及已登记用户工程的
`.codex-map-transaction-*` 日志。恢复失败只进入管理员状态和运维事件，不阻塞普通聊天或地图读取；状态包含
扫描工程数、已恢复事务、完成收尾、回滚数量和冲突目录。当前 `saveTransaction()` 仍是 4 MiB 小文件事务，
大 `.tmj` 仍由 `MapSaveSessionStore` 分块生成候选；项目事务现在接受受控候选文件引用（候选路径、大小和 SHA-256），
会在暂存目录内流式复制后再参与同一份多文件日志和原子提交，不把 4 MiB 内联内容上限扩大成地图上限。

本轮已将普通 `.tmj` 分块保存的提交桥接到项目事务：候选先经独立 Tiled 校验，再由
`MapProjectResourceWriter.saveTransaction()` 流式复制、校验哈希并原子发布，最后由保存会话确认事务返回的
路径/大小/版本后收尾。事务失败不会替换正式地图；候选会随保存会话清理。管理员恢复接口只允许可写工程，返回
脱敏工程标识，不返回绝对路径；4321 救援窗口仍不提供该接口。

World（`.world`）和外部瓦片集（`.tsj`）保存也已使用同一候选事务桥接。AI 托管地图执行器在生产接线中同样先
生成候选、再次检查实时授权，再交给项目事务发布；只有测试/旧嵌入器未提供项目事务写入器时才保留单文件回退。

图片候选发布和跨工程导入也纳入同一张管理员事务视图：`/api/ops/map-resource-transactions` 同时读取
`.codex-map-transaction-*` 与 `.map-asset-publication.json` 日志，返回事务类型、工程相对文件、阶段、文件数量和
哈希摘要，不泄露绝对路径；恢复接口按工程合并执行两类事务。图片发布恢复对正式输出使用流式 SHA-256 校验，
不会把整张大图读入主站内存。正在运行的图片发布候选目录会标记为 `protected` 并跳过管理员恢复，避免人工恢复
与当前发布并发时误删候选；恢复失败仍保留日志现场，且只进入管理员状态，不阻塞普通聊天。
地图资源事务（`.codex-map-transaction-*`）也登记进程内活动目录；管理员查询显示 `protected`，恢复会跳过
正在提交的地图/World/TSJ 事务。损坏日志单独记录为 `invalid` 并保留现场，不会阻止其他工程或普通对话恢复。

托管任务必须带幂等键、基础版本、目标文件清单、操作预算和权限快照。撤销授权不删除历史，也不强行终止已经进入
原子提交阶段的批次；该批次完成后立即停止后续批次并记录撤销原因。暂停同样是“当前批次完成后暂停”，不能在候选/事务
中途制造半保存；取消和人工接管则在每个实时授权边界硬停止。若取消、撤销或接管与原子提交竞态，迟到的 `committed`
检查点只允许记录已经发生的目标版本和操作索引，不得把终态任务复活为 `queued`、`paused` 或可恢复任务；失败/冲突终态也拒绝
后续新批次。服务重启时 `cancel_requested` 直接收敛为 `canceled`，不能通过未知提交确认重新启动。修订恢复在候选准备和项目
事务校验边界都重新比较人工/锁定保护基线。

## 22. 安全与隔离

- 所有项目、地图、World、TSJ、模板和素材路径都必须经过工程相对路径、realpath、符号链接和类型校验；
- 项目树列出文件不代表地图会话已授权读取文件内容；资源仍按会话清单和用途授权；
- `.tiled-project` 中的 extensions 目录不得被浏览器或主站执行；
- `.world` patterns 必须限制正则复杂度、扫描目录和文件数量，避免正则/目录资源耗尽；
- 图片缩略图通过受限图片接口和内容哈希读取，不接受外部 URL；
- 对象 file 属性、模板和 TSJ 引用不能越过工程根；
- AI 工具不能接收绝对路径、任意文件内容、地图 bearer 或浏览器认证凭据；
- 主窗口、editorInstance、Thread、project、map session 任一不匹配都撤销游戏模式；
- 托管授权另外绑定 `authorityMode=managed`、地图范围、操作范围、保护规则、幂等键和过期时间，不要求
  `editorInstance` 存在，也不能把编辑器租约升级成托管租约；
- 托管授权的 `approvalPolicy` 只能是 `ask_each`、`ai_review` 或 `full_authorization`；服务端拒绝未知值，不能由
  AI 工具参数临时改变；
- `ai_review` 必须产生可审计的风险分类和审查摘要；审查结果不能覆盖安全硬门槛，也不能自行授予新的地图范围；
- `full_authorization` 仍受授权范围、操作白名单、预算、版本和路径校验约束，不能等同于主站或 Shell 的完全访问；
- 地图工具目录可以稳定公开，但未授权调用必须 fail-closed 返回 `MAP_AI_AUTH_REQUIRED`，不能因为隐藏工具而让
  AI 改用通用文件写入；
- 直接应用只接受结构化 Tiled 补丁，不接受完整任意文件替换；TMJ、TSJ 和图片的多文件修改必须走事务清单；
- 人工锁定图层、对象、区域和文件在服务端重新检查，不能只依赖浏览器遮罩；
- 托管任务的每个批次都记录发起 Thread、授权快照、基础/目标哈希、补丁摘要和验证结果；
- 账号切换、密码修改、账号禁用、退出登录、删除 Thread 和关闭用户开关立即撤销相关租约；
- Worker 使用独立进程/cgroup、输入暂存、输出目录和内存/超时预算；
- 任何 OOM、供应商异常或解码失败只失败对应任务；
- 普通聊天服务在地图 Worker 全部关闭时仍可用。

## 23. 性能与缓存

### 23.1 浏览器

- 大地图只实例化视口和固定 overscan 内瓦片；
- tile data 编辑不为整张地图再创建第二份完整数组；
- World 邻图按边界/预览/完整地图分级加载，但分级由文件和用户设置决定，不根据负载自动切换；
- 图片和纹理按内容哈希、工程、用户授权及渲染参数缓存；
- 项目树、素材库和瓦片色板必须分页/虚拟化；
- 大 fill、Terrain、Automapping、缩略图和图片像素操作进入浏览器 Worker；
- 隐藏/关闭图层和标签后释放 Sprite、Texture 引用和事件监听；
- 手机内存不足时明确失败或要求用户关闭标签，不能静默降低资源质量。
- AI 托管上下文默认只保留地图结构摘要、选区引用、哈希和有限差异；图片缩略图、渲染结果和完整 tile data
  不进入长期对话，除非用户在当前任务中明确请求；
- 同一任务重复读取的资源按内容哈希去重，任务结果以版本凭据和预览任务 ID 代替重复传图。

### 23.2 服务端

- 地图、项目树、任务和资源清单都使用有界分页及流式读取；
- 普通 `/api/files/read` 的 1 MiB 边界不变；
- 地图、World、TSJ 和多文件事务使用专用版本化接口；
- 瓦片缓存和图片缓存继续使用管理员独立预算；
- 状态面板只显示 CPU、可用内存、主站延迟、Worker 数、队列长度和当前手动预设；
- 指标不得触发自动并发、画质、帧率、分辨率、缓存或渲染方式变化。

## 24. 可访问性与操作一致性

- 所有图标按钮具有中文 tooltip 和 aria-label；
- 画布工具使用稳定尺寸，选中、禁用、锁定和忙碌状态可辨识；
- 键盘焦点不被画布吞掉，输入框内快捷键不触发地图操作；
- 撤销、重做、保存、取消当前操作、平移、缩放和常用工具提供一致快捷键；
- 颜色不是状态的唯一表达方式；
- 对话、任务、图层和属性面板支持键盘导航；
- 手机文本和按钮不重叠，安全区和软键盘弹出后仍可提交；
- 不使用教程式首屏代替实际编辑器；新手帮助通过名称、上下文操作、空状态和工具提示完成。

| 风险 | 控制措施 |
| --- | --- |
| 宣称兼容但显示错误 | 解析/渲染/编辑/保存四级矩阵和官方夹具像素验证 |
| 项目树扩大文件权限 | 列表与内容授权分离，realpath、符号链接和会话复验 |
| 图片变换破坏 Tiled | image layer 只写原生字段；缩放旋转使用 tile object 或派生文件 |
| 多文件导入部分成功 | 暂存、清单、版本、原子提交和恢复事务 |
| World 占用过多内存 | 当前地图完整加载、邻图边界/预览、显式 adjacent 策略 |
| AI 串线程或旧提案写入 | 九维租约、editorState、版本和提案哈希复验 |
| AI 权限过大或用户误以为只是建议 | 三态协作模式、授权范围/有效期/操作卡、托管状态常驻显示 |
| 人工与 AI 互相覆盖 | 保护区、严格基础哈希、脏状态提示、暂停/接管和服务端冲突拒绝 |
| AI 每一步都打断用户导致无法连续工作 | `ai_review` 按固定风险规则批处理；`ask_each` 才逐操作询问；`full_authorization` 按授权范围连续执行 |
| AI 结果难以审查 | 结构化差异、影响热区、文件清单、校验摘要、版本凭据和一键恢复 |
| 关闭编辑器后任务丢失 | 持久托管任务、服务端事件序号、重启恢复和不确定提交检查 |
| 工具不可见导致 AI 绕过地图协议 | 稳定工具目录、结构化授权错误、拒绝通用文件工具代替地图提交 |
| AI 审查被误解为 AI 可以自我授权 | `ai_review` 使用版本化固定规则；AI 只解释结果，授权范围和硬门槛仍由服务端决定，审查摘要可审计 |
| 完全授权扩大成服务器完全访问 | `full_authorization` 只作用于已选工程/地图/操作白名单和有效期，不等于 Shell 或主站完全访问 |
| 批准策略变化造成运行中任务行为漂移 | 任务和批次保存策略快照；运行批次保持原参数，撤销/紧急暂停只阻止后续批次 |
| 风险规则随运行负载漂移 | `map-risk-v1` 固定阈值和规则快照，不读取 CPU、内存、设备、队列或模型意见，不在线热改阈值 |
| 图片撑大对话上下文 | 游戏模式显式租约、SHA-256 引用、普通对话完全分离 |
| 供应商尺寸不一致 | 操作级能力矩阵、提交前计划、实际尺寸校验、拒绝自动降级 |
| Tiled 工程脚本执行任意代码 | 不执行项目 extensions，后续仅管理员审计沙箱插件 |
| 大操作阻塞主站 | 浏览器 Worker/独立 Render 或 Image Worker，主站只调度和提交 |
| 手机功能被阉割 | 相同数据和命令模型，仅改变面板布局和触控方式 |

## 31. 结构化保护目标（已落地）

托管 AI 的 `protectedTargets` 现在使用统一合同。历史字符串仍兼容为文件保护：

```json
{ "kind": "file", "path": "maps/world.tmj" }
```

地图内保护目标使用工程相对地图路径和稳定 ID：

```json
{ "kind": "layer", "mapPath": "maps/world.tmj", "layerId": 3 }
{ "kind": "object", "mapPath": "maps/world.tmj", "layerId": 5, "objectId": 42 }
{ "kind": "region", "mapPath": "maps/world.tmj", "layerId": 1, "rect": { "x": 10, "y": 8, "width": 20, "height": 12 } }
{ "kind": "semantic", "mapPath": "maps/world.tmj", "layerId": 5, "role": "spawn" }
```

保护判断在三个阶段重复执行：Worker 预览前拒绝命中保护目标的操作，候选生成后比较受保护切片/对象的结构化快照，原子保存的两次授权回调之间再次比较当前文件。这样 AI 不能通过改名、改类型、改属性、换层或绕过浏览器直接提交来解除保护。`collision`、`spawn`、`teleport`、`portal`、`exit`、`trigger`、`checkpoint` 和 `interactive` 等语义对象可由名称、类型、Class 或属性识别；语义识别只是保护辅助，稳定的 layer/object ID 仍是首选。

## 33. 地图编辑器托管授权卡（已落地）

地图编辑器的“AI 地图补丁”窗口现在同时提供独立的托管授权卡。它明确区分短期、绑定编辑器实例的协作 lease 与可在关闭编辑器后继续运行的用户级 `managed` 授权。创建授权必须由用户勾选确认，并显示当前 Thread、地图相对路径对应的基础 SHA-256、允许操作、预算、保护目标和有效期；默认批准策略为“每条询问”，可显式选择“AI 审查”或“完全授权”。

授权卡只调用现有 `/api/map-ai/managed-authorizations` CRUD，不会在创建时启动任务或写入地图。撤销会先持久化撤销状态，再取消该授权的后续托管批次；地图版本变化显示为过期范围，后端仍会在每次任务创建和执行前拒绝旧版本。普通对话、图片字节和编辑器 lease 不会因为打开授权卡而进入托管工具上下文。

授权详情审计抽屉已补齐：授权 Store 保存有界的创建/撤销/过期事件，过期授权保留脱敏记录但从工具解析中移除；服务端提供仅限授权所有者的只读审计接口，编辑器可打开审计抽屉查看事件时间和原因，不返回绝对工程路径、令牌或图片数据。撤销确认仍使用编辑器内置可访问对话框，不依赖 `window.confirm`。真实浏览器端创建/撤销/版本冲突回归和候选部署仍待后续发布门槛执行。

## 34. 主界面托管授权卡（已落地）

主界面的“地图工作区”现在可以在不打开地图编辑器窗口的情况下管理 headless 托管授权。用户输入工程相对 `.tmj` 路径后，先通过当前项目会话读取真实文件 SHA-256；只有版本读取成功、账号地图工具开关已开启、当前 Codex Thread 确实属于当前工程，并且用户明确勾选范围确认，创建按钮才可用。授权列表按工程指纹、Thread 和地图相对路径过滤，不显示其他工程或其他对话的授权。

## 57. 角色动作编辑器专项长期计划（2026-08-14，计划已登记，尚未完成）

### 57.1 专项定位与恢复规则

之前的地图工作区计划已经覆盖 Tiled 地图、瓦片集、图片层、对象、碰撞和瓦片动画；这些内容不能代替角色动作编辑器。
角色动作编辑器是“游戏编辑器”的独立子工作区，面向角色精灵图、动作片段、锚点、碰撞框和运行时导出。它不是把人物
动作硬塞进 `.tmj`，也不是把一张角色图自动改写成 Tiled 瓦片集。

本节是角色动作部分的权威开发记录。以后发生上下文压缩、窗口切换或 Goal 恢复时，必须先读取本节的状态和完成定义，
不能根据某个已经存在的模型文件、页面入口或测试夹具推断整项功能已经完成。

当前基线：主站工作区候选 `0.43.55-beta`（发布前）；角色动作编辑器已经有独立页面、基础预览、工程资源读取、版本化保存和工具箱入口，
但尚未完成碰撞/攻击框、运行时导出、AI 角色工具、完整移动端回归和候选验收。页面存在不等于专项整体完成。

### 57.2 产品目标

用户从主界面的“游戏编辑器”进入当前工程后，可以打开“角色编辑”，选择工程内 PNG/WebP 精灵图或图片集合，建立多个
动作片段并实时预览。动作在不同帧之间必须保持明确的基准锚点和显示尺寸，不能出现角色因为抬脚、攻击、跳跃或特效而
自动忽大忽小。

第一阶段必须同时适配以下三种常见游戏类型，并保留自定义模式：

- 俯视角 RPG：四方向或八方向的待机、行走、奔跑、攻击、受击、死亡、施法和交互；脚底或角色中心作为稳定基准；
- 横向动作：左右朝向、待机、移动、跳跃、下落、攻击、受击、死亡和特效动作；角色脚底线和碰撞基准稳定；
- 第一人称：手臂、武器、换弹、开火、受击、交互和视角动画；武器/手部中心与屏幕参考点稳定；
- 自定义：用户自行定义精灵图网格、动作片段、锚点、显示高度、帧时长和碰撞数据。

不把三种视角强行统一为同一套行列约定。视角只是默认模板，最终数据仍由明确的帧矩形、动作片段和锚点决定。

### 57.3 数据文件和文件边界

角色美术、角色动作清单和运行时代码继续保持独立文件：

```text
assets/characters/hero.png                 # 原始或发布后的独立图片
assets/characters/hero.character.json      # WFL 角色动作清单
assets/characters/hero.preview.json        # 可选的预览/审查记录，不是运行时必需
src/...                                    # 游戏运行时加载器和逻辑
```

角色清单使用版本化的 `wfl.character-animation.v1`，至少包含：

- `source.path`、真实图片宽高、帧宽高、margin、spacing、列数和行数；
- `profile`：`topdown-rpg`、`side-scroller`、`first-person` 或 `custom`；
- `render.referenceHeight`、`render.scaleMode` 和固定像素锚点；
- 动作片段 `clips`：稳定 ID、名称、标签、是否循环、方向、帧序列和每帧时长；
- 可选的每帧偏移、朝向、镜像、事件标记和动作说明；
- 伤害框、受击框、交互框和脚底/武器/手部等语义锚点；
- 创建者备注和未知字段。

解析、保存和补丁必须保留未识别字段。图片不得 Base64 内嵌到清单，清单不得保存供应商 File ID、绝对路径、URL 或
临时文件句柄。源图实际解码尺寸、声明尺寸和保存前 SHA-256 必须一致；不一致时明确失败，不能裁切、缩放或静默替换。

### 57.4 编辑器界面

游戏编辑器主入口需要从“地图编辑器/地图工作区”逐步改成“游戏编辑器”，但地图、World 和瓦片集仍保留各自明确的
子编辑器名称。主界面工程侧栏增加：

- “打开游戏编辑器”按钮；
- “角色编辑”按钮；
- 当前工程角色图片、角色清单和动作资源筛选；
- 当前打开的地图、World、瓦片集和角色编辑窗口标签；
- 当前工程、Thread、用户和窗口隔离状态。

角色编辑器使用独立、按需加载的 `character-editor.html/js/css`，不能把图片解码器、时间轴和预览纹理常驻主聊天页面。
桌面提供三栏布局：

```text
左：工程图片/角色清单/动作片段
中：精灵图网格、选帧、锚点、基准线、洋葱皮和缩放预览
右：源图网格、动作属性、帧时长、碰撞框和导出状态
下：时间轴、播放/暂停、循环、逐帧步进和当前事件
```

平板允许收起左右面板但不删除功能；手机使用“资源 / 画布 / 动作 / 属性 / 时间轴”标签或抽屉，触控目标保持可用，
不自动降低预览质量或切换到功能缩水模式。页面关闭、刷新、切换工程或切换账号时，未保存动作必须明确提示。

### 57.5 精灵图切帧和动作片段

- 支持规则网格切帧：帧宽、帧高、margin、spacing、列数和行数均由用户确认；
- 支持从图片集合逐张建立稳定帧 ID；
- 支持手动选择任意帧组成动作，不要求动作必须占据连续的一行；
- 支持帧顺序、帧时长、循环、反向、Ping-Pong 和动作标签；
- 支持复制动作、重命名动作、调整动作顺序和删除动作；
- 支持动作级默认锚点与帧级显式偏移；
- 支持动作预览、固定速度、固定显示高度、逐帧暂停和基准线叠加；
- 先实现帧动画，暂不把骨骼动画、Spine、DragonBones 或任意第三方运行时作为第一版硬依赖；
- 后续可以增加骨骼/插值适配器，但不能破坏 `wfl.character-animation.v1` 的帧动画兼容性。

默认模板只提供建议，不根据设备、CPU、图片大小或模型意见自动改变帧数、分辨率、画质、播放方式或并发。

### 57.6 角色大小、锚点和动作一致性

这是角色动作编辑器的硬验收重点。必须同时保存并显示：

- 精灵图原始像素尺寸；
- 每帧实际矩形；
- 脚底、中心、武器、手部或屏幕参考点等锚点；
- 动作预览的固定参考高度；
- 可选的人工帧偏移和人工缩放修正。

默认规则为：

1. 运行时使用动作清单的 `referenceHeight` 或明确的人工缩放值；
2. 每一帧先按同一参考尺度绘制，再应用明确保存的锚点和偏移；
3. 系统不根据每帧透明像素包围盒自动缩放角色；
4. 系统不因为某一帧尺寸不同而自动裁切、补边、重采样或换画质；
5. 检测到脚底线、主体高度或锚点偏差时只给出诊断和可视化标记，修正必须由用户确认；
6. 预览、导出和 `wflgame` 运行时使用同一套锚点和参考高度计算。

可提供“按当前帧建议锚点”“按动作统计包围盒”“复制上一帧偏移”等显式按钮，但这些都是一次性人工确认操作，不能
变成后台自适应规则。严格模式下，所有帧的核心锚点必须相同；宽松模式只允许记录差异，不能隐藏差异。

### 57.7 碰撞、攻击和语义框

角色动作数据与地图碰撞数据分开，但可以由游戏编辑器统一查看。第一版支持矩形、圆/椭圆、多边形和点状锚点：

- hurtbox：角色受击范围；
- hitbox：攻击或技能命中范围；
- interaction：拾取、交互和对话范围；
- foot：脚底/移动基准点；
- weapon、hand、muzzle、head 等可选动作锚点；
- 每帧或动作级数据，动作级默认值可以被单帧覆盖；
- 所有框都能在画布和预览中切换显示，导出时不烘焙进图片。

运行时能力探测必须确认当前 `wflgame` 加载器是否支持该语义。若不支持，编辑器可以保存为只读扩展数据，但 AI 托管和
自动发布必须返回明确的 `RUNTIME_CHARACTER_FEATURE_UNSUPPORTED`，不能把数据写入后假装游戏一定会使用。

### 57.8 内置生图和素材发布

角色编辑器复用现有独立图片 Worker，但和普通对话图片保持隔离。计划增加：

- 生成角色整张精灵图；
- 根据参考图编辑角色姿态或服装；
- 扩图以补全动作画布；
- 生成同角色不同方向、动作或表情候选；
- 生成透明背景角色、武器、特效和动作素材；
- 生成结果先进入候选区，显示真实尺寸、透明度、哈希、供应商操作和输入是否实际消费；
- 只有用户明确发布后，图片和角色清单才进入工程；
- `PNG/WebP + character.json` 发布使用全成或全不成事务，不能只发布清单或只发布图片；
- 供应商不支持目标尺寸时明确失败，不自动改尺寸、降质量、裁切或重试成另一种操作。

角色编辑器显示候选缩略图不等于把完整图片再次注入对话。游戏工作模式下只发送有界的资源元数据、哈希、尺寸、动作
摘要或用户明确选择的裁剪引用；普通对话仍保持原有的完整图片附件行为。

### 57.9 AI 工具和人机协同

角色工具必须使用独立、稳定、可发现的工具目录，不能要求用户打开角色编辑器才能让 AI 使用；打开编辑器后只是提供
可视化观察、提案、审批和实时刷新。计划中的工具包括：

- `inspect_character_asset`：返回角色清单、图片尺寸、动作摘要、锚点和运行时能力；
- `read_character_clip`：按动作和有限帧范围读取结构化数据，不默认返回整张图片；
- `validate_character_asset`：检查尺寸、帧矩形、锚点、时长、碰撞框和运行时支持；
- `propose_character_animation_patch`：生成结构化动作修改提案；
- `apply_character_animation_patch`：在授权和基础哈希匹配时提交补丁；
- `list_character_assets`：分页列出当前工程已授权的角色图片、清单和候选资源；
- `publish_character_candidate`：在用户明确确认后发布图片与清单事务；
- `preview_character_animation`：只生成有界预览状态或 Worker 任务，不把结果自动塞回对话。

统一补丁合同为 `wfl.character-animation.patch.v1`。每个操作必须有目标文件、`baseHash`、动作/帧范围、预期影响和幂等键；
禁止 AI 直接提交任意 JSON 全文件覆盖、绝对路径、图片字节、Shell 命令或供应商 File ID。服务端在 Worker 预览、候选生成、
原子保存前重复校验路径、哈希、图像实际尺寸、动作帧和运行时能力。

协同模式沿用游戏编辑器现有三档，但不与普通对话批准策略混淆：

- 每条询问：每个动作/帧/碰撞框写操作单独显示差异和批准卡；
- AI 审查：使用版本化固定风险规则，AI 只能解释审查结果，不能自我授权；
- 完全授权：只取消逐条询问，仍保留路径、版本、运行时、尺寸和保护目标硬门槛。

用户可以锁定角色清单、动作片段、帧范围、锚点、碰撞框和发布目录。主界面、游戏编辑器和独立角色窗口显示同一任务
状态；关闭角色窗口后，已明确授权的托管任务可以继续，但不会自动扩大范围。版本冲突、撤销授权、窗口关闭和主站重启
必须进入可查询状态，不能静默覆盖人工修改。

官方 Codex 子代理可以承担小型、边界清晰的模型测试、UI 契约测试、文档审查和低风险辅助编程；角色资源写入仍必须经过
宿主指定的工程、Thread、角色、权限和批准策略，不能由子代理覆盖。官方子代理不获得绕过角色工具、
文件版本或人工批准的特殊权限。

### 57.10 `wflgame` 运行时联动

先对 `/srv/wflgame` 做只读能力探测，确认当前 Phaser 加载器的角色清单入口、纹理缓存、动画注册、方向映射、锚点使用、
碰撞/攻击框消费方式和热更新边界。第一版优先提供一个明确的 WFL 运行时适配层：

- 角色清单加载不改变 Tiled 地图文件；
- 纹理按工程相对路径加载并验证实际尺寸；
- 动作片段按稳定 ID 注册；
- 参考高度、锚点、动作事件和碰撞框使用同一规则；
- 缺失动作、坏帧、尺寸不符或不支持语义在运行前报告；
- 不在游戏运行时自动猜测动作、不自动替换图片、不自动降低画质；
- 旧项目没有角色清单时继续使用原有代码路径，不强制迁移全部角色。

### 57.12 角色动作专项验收标准

只有满足以下条件，角色动作编辑器才可以称为“完成”：

- 用户可以从游戏编辑器进入角色编辑，而不是手工改 JSON；
- 工程图片、角色清单、地图和运行时代码保持独立文件；
- 同一角色可以创建多个动作、方向和帧序列，并保存帧时长与循环设置；
- 预览和运行时使用同一锚点、参考高度和缩放规则，动作不会未经授权自动变大或变小；
- 锚点偏差、图片尺寸不符、帧越界、时长无效和运行时不支持均有明确错误或警告；
- 碰撞框、攻击框、受击框和动作事件可视化且不烘焙进图片；
- AI 可以在不打开编辑器时使用受限角色工具，打开后能看到同一版本和差异；
- AI 修改采用结构化补丁、基础哈希、审批/托管和可恢复历史，不能通过通用文件工具绕过；
- 图片生成、编辑和扩图结果只有显式发布后才进入工程，尺寸和透明度经过实际校验；
- 游戏模式不会把角色大图、预览视频或重复帧自动塞入长期对话；普通对话图片行为不变；
- 俯视角 RPG、横向动作和第一人称模板都能完成最小待机/移动/动作流程；
- `wflgame` 能力不足时拒绝不支持的自动发布，不伪装兼容；
- 普通用户服务器不运行物理输入或大规模压力验收；这些仍是独立、明确的后续门槛；

## 58. 工具箱与图片隔离双开关（2026-08-14，方案已确认，待实施）

本节记录用户确认后的简化操作方案，优先级高于前文把“游戏工作模式”与地图编辑器窗口绑定的旧界面描述。目标是减少
普通用户必须理解的权限项，同时保留服务端的工程边界、版本校验、原子保存和可恢复历史。当前只登记方案，未因本节
递增版本、修改前端代码或部署。

### 58.1 顶部工具箱入口

对话界面顶部原来的“地图”按钮改名为“工具箱”，图标、按钮标题、ARIA 文案、帮助说明和移动端入口统一使用“工具箱”。
工具箱可以在不打开游戏编辑器的情况下打开，内容按需加载，不能把地图编辑器、角色编辑器或图片解码器常驻主聊天页面。

工具箱的第一批子工具为：

- 地图 / World / 瓦片集编辑；
- 独立角色动作编辑器；
- 素材库和资源索引；
- 图片生成、编辑、裁剪和扩图；
- 游戏预览、截图和导出。

地图编辑器和角色动作编辑器是工具箱中的可选窗口，不再作为图片隔离功能的前置条件。打开窗口后，窗口只观察和操作
当前主界面的工程、Thread、任务、版本和差异；关闭窗口不关闭任何主界面开关。

### 58.2 两个且仅两个普通用户开关

主界面工具箱和相关移动端面板只显示以下两个开关：

```text
[ ] 隔离上下文图片
[ ] 允许 AI 使用游戏编辑工具
```

两个开关独立，不存在一个总开关暗中修改另一个：

| 开关 | 作用域 | 开启后的固定行为 |
| --- | --- | --- |
| 隔离上下文图片 | 当前用户 + 当前工程 + 当前 Thread；无工程时为当前用户 + Thread | 图片索引、哈希去重、缩略图联系表、分批分析、摘要和按需原图读取 |
| 允许 AI 使用游戏编辑工具 | 当前用户 + 当前工程 + 当前 Thread | AI 可使用地图、角色、瓦片集、素材、预览和导出工具，但不能越出当前工程 |

四种组合必须稳定且可解释：

- 两者关闭：普通对话；明确附加的图片按普通规则处理，不使用游戏工具；
- 只开图片隔离：可以在任何普通或非游戏对话中批量分析图片，但不修改游戏文件；
- 只开游戏工具：AI 可以操作当前游戏工程，图片仍按普通规则处理；
- 两者都开：完整游戏协作，AI 可以修改工程，同时图片上下文按隔离规则处理。

不再向普通用户暴露“地图工具权限”“角色工具权限”“单图授权”“每次读取审批”“编辑器租约”“图片批次大小”
等额外开关。服务端仍保留必要的外层能力校验，但这些是固定安全边界，不是日常操作流程。

### 58.3 通用图片分析流程

“隔离上下文图片”不能命名或实现成游戏专属功能，必须覆盖设计稿、产品图、资料审查、参考图对比和其他普通图片任务。
用户可以拖入多张图片、选择目录或直接要求“分析当前对话中的全部图片”，不要求逐张选取。

固定流程如下：

1. 服务端建立当前 Thread 的图片索引，记录相对路径或附件标识、尺寸、格式、SHA-256 和缩略图；
2. AI 先获得有界资源清单和缩略图联系表，再按任务需要读取相关原图；
3. 相同哈希的图片只向模型交付一次，后续使用当前对话的摘要和引用；
4. 多图片任务由系统固定分批和排队，用户不需要调整 Token、批次或并发参数；
5. 已完成分析保存为当前 Thread 的结构化摘要，原始图片字节不写入长期记忆；
6. 图片哈希变化后作为新版本重新分析，不能用旧摘要假装代表新图片；
7. 工具箱、编辑器候选列表、图片目录和预览结果不会自动把完整图片注入对话。

系统不根据图片数量、模型建议、设备、CPU、内存或服务器负载自动切换图片隔离、画质、并发或读取方式。用户关闭
开关后恢复普通图片行为，用户开启后始终遵守隔离规则。

### 58.4 角色动作编辑器在工具箱中的位置

第 57 节的角色动作专项仍是角色功能的权威开发计划。本节补充其入口和协同关系：

- 工具箱直接提供“角色动作编辑器”入口，不需要先打开地图编辑器；
- 角色编辑器支持精灵图导入、批量切帧、动作片段、时间轴、锚点、固定参考高度、洋葱皮、碰撞/攻击/受击框和预览；
- 角色动作编辑器适配俯视角 RPG、横向动作、第一人称手部/武器动画和自定义模板；
- “允许 AI 使用游戏编辑工具”覆盖角色动作编辑，不再增加单独的角色权限开关；
- AI 可以在角色编辑器未打开时读取、校验和提交结构化角色补丁；打开后主界面可以同步查看版本、差异和预览；
- 角色图片、角色动作清单、预览记录和运行时代码继续保持独立文件；
- 角色尺寸、基线、锚点和帧时长必须由明确数据控制，不能因透明包围盒或模型建议自动缩放；
- 生成/编辑/扩图候选只有在用户明确发布后才进入工程，图片和角色清单必须原子发布并保留可撤销版本；
- 开启图片隔离时，角色大图、动画预览和重复帧不能自动全部注入对话，AI 使用资源索引、动作摘要和按需帧读取。

### 58.5 简化后的固定安全规则

取消日常逐项权限操作不等于取消工程安全边界。所有游戏工具写入统一执行：

- 当前账号、工程和 Thread 校验；
- 工程相对路径校验，禁止绝对路径、越界、URL、Base64 和 Shell 命令；
- 基础版本哈希校验和并发冲突返回；
- 地图、角色清单、图片和预览文件的原子保存；
- 自动保留历史版本，支持撤销和恢复；
- 删除优先进入可恢复回收区，不立即物理删除；
- 工具调用、文件变化、基础哈希和结果写入任务记录；
- 不支持的 Tiled、角色运行时或图片供应商能力必须明确失败，不能自动降级或偷偷换参数。

“完全授权”等高级托管细节如果继续保留，只能放在折叠的高级面板中，不能成为普通工具箱使用前提，也不能改变上述硬
安全边界。

用户再次发现终止按钮提示“已清除”但实际任务仍为运行中，本项加入游戏编辑器长期更新的 P0 稳定性门槛：
