# 多用户安全与运维说明

## 默认行为

多用户功能默认关闭。关闭时继续使用原有单用户密码、项目目录、Codex 登录
和供应商库，不会自动迁移或删除现有数据。所有者从设置进入独立的 `/users`
用户管理页并重新输入当前
网页登录密码后，才会创建邀请制账号模式。

## 账号与权限

- 邀请令牌只保存哈希，默认 24 小时过期且只能使用一次；公开注册永远不会打开。
- `owner` 可以启用/关闭多用户、管理所有账号、分配供应商和执行主机升级。
- `admin` 可以管理普通成员、创建自己的供应商并把自己有权使用的供应商复制给成员，
  也拥有版本、插件和 SSH 管理能力；应把管理员视为主机受信任运维人员。
- `member` 只能使用自己的工程、对话和被授权的共享工程；管理员可以单独允许成员保存
  自己的自定义供应商，未授权时只能使用管理员分配的供应商。成员不能安装插件或升级主机。
- Claude Code 的运行、官方登录、API 供应商、扩展、MCP、Hooks、Memory、后台 Agent、
  Worktree、账号代理、结构化输出、Ultra Review、工程清理和 Beta Header 分别授权。
  套餐、默认策略和单用户编辑使用同一组权限；网页隐藏按钮不能代替服务端鉴权。
- 管理员撤销 Claude 运行或语义能力时，正在执行的任务会在当前安全边界暂停，等待重试的
  任务立即转为持久暂停；不会封锁用户对话，也不会在权限恢复后自行重放可能有副作用的任务。
- 停用会删除所有该用户会话、关闭实时连接并停止该用户 Codex 子进程；重新启用会
  创建新的运行上下文。删除账号不是当前版本的网页操作，避免误删数据；停用后可
  先备份再由主机管理员清理 Linux 账号和 HOME。

## 隔离模型

每个成员使用不可登录的 Linux 系统账号、独立 UID/GID、`0700` HOME、`CODEX_HOME`、
工程目录、恢复状态、加密供应商库和 Codex Bridge。HTTP/WebSocket 会话使用哈希
令牌、HttpOnly、SameSite-Strict 和 7 天有效期；登录、注册和写操作要求同源来源。
项目、文件预览、上传、下载、恢复记录和 RPC 工作目录都经过真实路径和符号链接检查。
普通成员的状态接口只返回本人空间用量和额度，不返回主机 CPU、内存、整盘容量或运行时间。
上传已有工程时只接受 `.tar.gz`；服务端在临时目录检查路径穿越、链接、特殊设备、
保留目录、条目数、解压大小和用户空间额度，通过后才把工程切换到正式目录。

共享工程使用显式的只读或可编辑授权，并由 Linux ACL 同时约束网页和成员 Codex 子进程。
只读共享适用于应用配额和硬配额；可编辑共享只允许分配给启用了文件系统硬配额的用户，
避免写入其他 HOME 的数据绕过个人额度。撤销共享、关闭共享权限或停用账号会同步撤销 ACL。
Ubuntu 限制非特权 `userns` 时，发布流程安装仅限 Codex 到 bubblewrap 子进程的 AppArmor
转换配置，不会全局关闭该内核限制。

这是主机账号隔离，不是容器隔离。后端仍以 root 运行，成员可以读取世界可读的主机
文件；Codex 工具是否允许联网由官方 Codex 沙箱和主机网络共同决定。不要在同一台机器
上放置其他生产服务或邀请不可信租户。需要强租户隔离时使用独立 VM/容器、网络策略、
只读镜像和单独的密钥管理。

## 配额

应用层在每次创建工程、上传和新任务前统计整个用户 HOME，包含对话、缓存和上传。
它是软限制，单个任务在两次统计之间可能短暂超出。硬限制要求 HOME 所在文件系统
启用 `usrquota` 或 `uquota`，并由 `setquota` 为对应 UID 设置限制；安装器只安装
`quota` 和 `acl` 工具，不会擅自修改 `/etc/fstab` 或重挂载生产文件系统。修改后必须用测试账号
验证创建、写入、删除、重启和恢复。

管理员还可以为用户设置滚动 5 小时、UTC 周一开始的自然周、UTC 自然月三档 Token
限额。计数只来自 Codex 官方 `thread/tokenUsage/updated`，不扫描对话也不估算；Codex
没有上报时显示“待上报”，该周期不会因未知用量误拦截。一个已开始的任务可以用完
剩余额度，达到限额后下一次任务会被拒绝。

## 备份、迁移与泄露处理

代码发布包、Git 同步和版本中心更新都不会复制账号数据。所有者可在
`/ops#backups` 使用备份中心创建 AES-256-GCM 加密、SHA-256 校验的数据备份，选择
每天或每周执行并保留 1 到 30 份。范围包括：

- `CODEX_DESKTOP_STATE_DIR` 的账号 JSON、共享授权、审计日志、`user-state/`、加密供应商密文和密钥；登录会话不进入备份。
- `CODEX_DESKTOP_MULTI_USER_ROOT` 下所有用户 HOME、工程、上传和 Codex 对话目录。
- 需要时再备份旧单用户的 `~/.codex`、项目和代理/Tunnel 配置。

备份文件和索引限制为 `0600` 并与代码仓库分离；恢复密钥需要单独导出保管。下载、
删除、策略设置、密钥导出和恢复都只有所有者可操作，其中危险操作还要复验密码。
不要把 API Key、会话 Cookie、
邀请令牌或 `users.json` 发到工单或聊天。迁移到新服务器前需要按原 UID/GID 创建系统
账号，再恢复文件；只复制 `users.json` 会得到不可用或错误归属的文件。网页恢复只允许
相同 `machine-id` 和相同应用版本，切换前等待任务结束，失败时保留原目录；它不是异机迁移工具。当前版本没有
跨服务器租户一键迁移工具，用户级项目下载和 Markdown/JSON 对话导出适合手动交接。

发现 API Key 泄露时立即在供应商侧撤销/轮换，并在网页删除或更新供应商；发现邀请泄露
时停用/废弃该邀请并重新生成；发现会话 Cookie 泄露时让用户退出或停用账号，必要时清空
`sessions.json` 后重启服务。审计日志只记录账号、时间、操作和对象 ID，不记录密码、Key
或对话正文。
