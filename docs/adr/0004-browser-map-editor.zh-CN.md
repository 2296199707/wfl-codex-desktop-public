# ADR-0004：浏览器地图编辑器、地图存储与隔离渲染边界

状态：已接受<br>
日期：2026-08-09<br>
范围：主站文件能力、独立地图编辑器、可选 Render Worker、桌面/平板/手机浏览器<br>

## 目标

WFL 增加按需加载的浏览器原生游戏地图编辑器。地图采用 Tiled JSON 兼容格式：地图为 `.tmj`，
外部瓦片集为 `.tsj`，图片、音频和游戏 HTML 继续作为工程内独立文件存在。编辑器完整支持桌面、
平板和手机，不把当前服务器的容量当成功能上限。

浏览器承担实时画笔、触控、选择、拖动、缩放、图层、撤销和交互预览。主站只承担身份、工程
授权、真实路径隔离、版本校验、文件事务和任务调度。高清截图、全景、切片、动画及批量导出由
独立本地 Render Worker 执行，不能进入聊天主站 Node 进程。

## 不变约束

- 不采用 Linux 桌面远程控制，不把桌面 Tiled 编辑器远程暴露给用户。
- 不把图片以 Base64 或 data URI 写入地图；所有资源引用必须解析为工程内相对路径。
- 不删除、重命名或规范化未识别的 Tiled 字段。读取、编辑已知字段和再次序列化后，未知字段的
  JSON 值及层级必须保持不变。
- 不向对话自动注入地图、图层或提示词。AI 入口首先只提供显式复制提示词及可审阅结构化补丁。
- 不自动选择并发、预设、分辨率、帧率、抗锯齿、渲染方式或画质，也不对最终导出自动降级。
- 管理员设置变更只形成新的不可变配置快照；运行中任务继续使用入队时的参数。
- Worker 不可用、超时或超过内存预算只影响对应渲染任务，浏览器编辑和主站保存保持可用。
- 冻结的救援窗口、`rescue-active-port`、端口 `4321`、救援服务、slot、资产和版本不属于本功能。

## 文档模型

第一阶段使用纯 ESM Tiled 文档核心，浏览器与 Node 聚焦测试共用同一实现。核心负责：

1. 识别 `map` 与 `tileset` 文档并校验必须的结构字段；
2. 遍历瓦片层、对象层、图像层和递归分组，接受有限地图 chunks 和编码后的 Tiled tile data；
3. 收集外部瓦片集、图片、对象模板和 `file` 类型属性引用，并将其解析到工程相对路径；
4. 拒绝绝对路径、URL、data URI、工程逃逸和无效 UTF-8；
5. 对未知图层类型给出警告但完整保留，对未知字段不做白名单重建；
6. 通过深克隆建立编辑副本，防止视图操作意外污染最后一次服务端版本。

出生点、传送点、碰撞和 LDtk IntGrid 风格语义使用普通 Tiled 对象、class/type、属性、瓦片层及
外部关卡文件表达，不引入不兼容的私有二进制地图格式。

### 编码瓦片与投影

Base64 只允许用于 Tiled 标准 tile data，不能用于图片、音频或其他资源。有限瓦片层和无限地图
chunks 在打开时解码成普通 GID 数组，支持未压缩 Base64、zlib 和 gzip；运行环境原生支持 zstd
时才接受 zstd，否则明确打开失败。解码过程检查 Base64 语法、解压后精确字节数、32 位 GID、
取消信号和解压上限，不能让压缩炸弹占用主站或浏览器的无界内存。

编辑文档、撤销栈和 AI 补丁始终操作数组。保存时只克隆导出副本，并按原图层或 chunk 的
`encoding + compression` 恢复编码；保存过程不能把编辑内存改回字符串，也不能因为浏览器或 Worker
不支持某种压缩而改成另一格式。新建 chunk 继承所属图层的原编码契约。

查看器支持 `orthogonal`、`isometric`、`staggered`、`hexagonal` 和 Tiled oblique 投影。画笔、
橡皮、选择、对象命中和拖动共用可逆投影；等距和 oblique 对象坐标按 Tiled 像素坐标转换，point、
text 和 GID 对象只转换锚点，不把内容仿射拉伸。六边形 GID 的 60°/120° 标志按 Tiled 语义组合。
未知 orientation 原样保留并告警，查看器按正交方式显示；不可逆 oblique 参数直接拒绝打开。

### 外部瓦片集边界

地图会话从 `.tmj` 递归读取被引用的外部 `.tsj`，使用 visited 集合终止循环，并把最终瓦片集、图片、
模板和 file 属性绑定到该地图内容版本的资源清单。资源接口只读取清单中的工程相对路径；未引用文件、
路径逃逸、跨工程路径和符号链接即使在工程目录附近存在也不能读取。

浏览器与 Render Worker 使用同一纯瓦片集布局校验。创建图集 frame 前必须确认 tilewidth、tileheight、
margin 和 spacing 是安全整数，TSJ 声明的 imagewidth/imageheight 与解码图片一致，columns 与实际可
容纳列数一致，tilecount 不超过真实 frame 容量。图片集合的 tile ID 必须为非负唯一整数，允许历史
删除形成的 ID 空洞；每张图片的声明尺寸也必须与解码结果一致。

加载全部瓦片集后按 firstgid 排序，使用真实最高本地 ID 计算 lastgid。firstgid 重复、瓦片集 GID
区间重叠或最高 GID 进入 Tiled 翻转标志位都直接失败。动画帧必须引用可渲染瓦片并使用正整数时长。
这些错误不能通过截短 tilecount、跳过 frame、重新编号 GID 或降低渲染质量继续。

图集 frame 按实际使用创建：只有地图单元、GID 对象、动画帧或当前瓦片色板页引用到本地 ID 时，
Pixi 才创建对应 Texture frame。瓦片色板固定每页 200 项并提供显式上一页/下一页，翻页只构建
当前页 DOM 和尚未使用的 frame，不能把 200 项当成功能上限；当前选中 GID 在翻页时保持不变。

交互查看器只为当前视口及固定瓦片外延创建 Sprite，平移和缩放在缓冲范围内复用实例，隐藏图层释放
其瓦片 Sprite；这只是浏览器内存边界，不改变地图数据。Worker 截图、全景、切片、动画和批量导出
仍按用户请求的完整覆盖范围渲染，不能沿用交互视口裁剪或因此减少、夹取或降级输出。

## 独立编辑器

入口使用独立 `map-editor.html`、`map-editor.js`、`map-editor.css` 和域模块。聊天页只在文件管理器
识别 `.tmj` 时显示“地图编辑器”命令；打开后在新浏览器上下文中加载，主聊天页不常驻 PixiJS、
地图数据、纹理或历史栈。

编辑器 URL 只携带短期服务端会话标识，不携带任意文件系统访问令牌。会话绑定：

```text
userId + authSessionId + projectRealPath + mapRealPath + editorInstanceId + expiresAt
```

每个窗口生成新的 `editorInstanceId`。窗口间不共享当前选择、撤销栈、脏状态或保存会话；它们只
通过同一内容版本产生正常的乐观并发冲突。第一版不引入 Yjs 或实时多人共同编辑。

## 地图读取协议

普通 `/api/files/read` 的 1 MiB 预览边界保持不变。地图使用专用接口，管理员可手动设置每段大小
和总任务上限，默认值只影响新会话：

- `POST /api/maps/sessions`：校验用户、工程、`.tmj` 文件和编辑权限，返回地图会话、内容 SHA-256、
  大小、修改时间、只读状态、手动配置快照和首段；
- `GET /api/maps/sessions/:id/content?offset=`：按会话固定段长返回原始 UTF-8 字节，要求客户端携带
  当前内容版本；文件发生变化时返回 `409`，不能拼接不同版本；
- `GET /api/maps/sessions/:id/resource?path=`：只读取会话工程内、Tiled 文档引用的 `.tsj`、图片和
  后续允许的音频资源；路径再次规范化和 realpath 校验，不能把浏览器声明当授权。

内容版本统一为完整文件字节的 SHA-256。元数据版本只用于目录刷新，不能参与地图保存冲突判断。
响应使用 `Cache-Control: no-store`；图片可使用带内容版本的私有缓存键。

## 分块原子保存协议

地图保存不扩大普通 JSON body 或 `/api/files/write` 限制，而使用独立事务：

1. `POST /api/maps/save-sessions` 提交地图会话、期望内容版本、总字节数、总 SHA-256 和客户端操作
   ID；服务端返回绑定当前用户/地图/窗口和配置快照的 `saveId`、固定 chunk 大小及过期时间。
2. `PUT /api/maps/save-sessions/:saveId/chunks/:index` 使用原始字节 body。每段携带 SHA-256；服务端
   以排他创建写入临时目录，重复上传只有在哈希一致时幂等成功。
3. `POST /api/maps/save-sessions/:saveId/commit` 检查段数、连续偏移、总长度、总哈希、有效 UTF-8、
   JSON/Tiled 结构、工程内资源引用、当前目标内容版本和用户配额。
4. 校验完成后在目标文件同目录创建临时文件，保留原 mode/uid/gid，写入并 fsync 文件，再以原子
   rename 替换目标并 fsync 父目录。任何校验或写入失败都保留原文件。
5. `DELETE /api/maps/save-sessions/:saveId` 显式放弃。过期会话由有界清理器删除；服务重启后不提交
   来源不明的临时数据。

提交前再次校验权限和当前版本，不能依赖创建 save session 时的旧授权。达到管理员手动并发上限
时进入 FIFO 队列；不得通过减少数据、改写 tile data 或降低输出质量绕过上限。

## 编辑和补丁契约

撤销/重做记录面向明确目标的结构化操作，而不是整份 JSON 字符串 diff。操作至少包含文档版本、
图层/对象稳定 ID、操作类型、旧值和新值。保存仍提交完整无损文档；结构化补丁用于本地历史、AI
预览和冲突说明，不能绕过服务端最终文档校验。

AI 提示词只在用户点击“复制地图编辑提示词”后由当前窗口本地生成。提示词只包含工程相对地图路径、
文件 SHA-256、本地编辑状态 ID、地图尺寸、图层摘要、瓦片集 GID 范围和当前显式选择；不包含完整
tile data、绝对工程路径、地图会话 ID、窗口凭据、认证令牌或对话内容，也不发起对话请求。

第一版 AI 补丁使用以下有版本协议：

```json
{
  "format": "wfl-tiled-patch",
  "version": 1,
  "base": {
    "mapPath": "maps/world.tmj",
    "mapVersion": "<64 位 SHA-256>",
    "editorStateId": 0
  },
  "summary": "修改说明",
  "operations": []
}
```

允许的操作只有 `set-tiles`、`fill-region`、`update-layer`、`add-object`、`update-object` 和
`remove-object`。解析阶段拒绝未知操作、受保护的图层结构字段、危险对象键、错误 Tiled 字段类型、
data/blob URI、绝对路径和工程逃逸引用；预览阶段再检查图层类型、锁定状态、编码 tile data、坐标、
GID 范围和全局对象 ID 冲突。

用户粘贴 JSON 后必须先预览。确认应用时再次逐项校验 `mapPath + mapVersion + editorStateId` 和原始
JSON；地图或补丁发生任何变化都要求重新预览。通过的混合操作进入当前窗口的一个原子撤销项，后续
操作失败时整批逆序回滚。应用只改变当前窗口内存，不自动保存、不写入其他窗口，也不注入任何对话。
地图 AI 协作现已采用默认关闭的用户级开关。用户必须在当前编辑器窗口显式绑定当前原生对话，服务端
签发短期租约并绑定以下九维上下文：

```text
userId + browserSessionId + threadId + projectPath + mapSessionId
+ mapVersion + editorInstanceId + editorStateId + allowedOps
```

租约 bearer 只在授权响应中返回并只保存在该窗口的 `sessionStorage`；服务端只持久化 SHA-256 摘要。
地图编辑器复制提示词时，只有仍匹配当前租约的窗口才附带四个非秘密工具上下文标识：
`threadId`、`mapSessionId`、`editorInstanceId`、`editorStateId`。绝不把租约、绝对工程路径、图片字节或
完整 `.tmj` 放进提示词、MCP 参数或对话记录。标准 MCP 没有可靠的当前 thread 所有权，因此工具服务拒绝
根据最近活动对话猜测上下文；零个或多个租约匹配都 fail-closed。

每个用户 Codex runtime 获得一个权限为 `0600` 的独立 `wfl_map_ai` Unix socket。MCP 只暴露
`get_map_context` 和 `propose_tiled_patch`：前者返回有限元数据，后者只把解析后的
`wfl-tiled-patch` 写入待审阅收件箱并返回不含 patch 正文的轻量回执。每次调用都重新验证 live 地图会话、
工程归属、地图 SHA-256、对话 `cwd`、写权限和编辑状态；工具阶段不能写 `.tmj`。提案由浏览器逐项预览，
确认后只进入撤销栈，再由用户自行保存；保存、关闭窗口、退出登录、对话删除、密码更新、账号禁用或
用户关闭开关都会撤销相关租约。普通本地编辑状态变化也会撤销旧租约，避免旧提示词继续提交提案。

图片与地图的视觉上下文另行隔离：图片字节默认只在图片工作室/视觉审查作用域内短期存在，只有用户
明确选择“加入对话”才附加完整图片；地图工具和视觉审查不能自动把图片注入长期游戏制作对话。

## Render Worker 与手动设置

Render Worker 是独立进程或服务，使用有界 IPC/本地套接字接收结构化任务。主站队列保存任务配置
快照，Worker 只得到当前工程的只读输入能力和单个输出暂存目录。内存预算、超时或子进程退出时，
主站把该任务标为失败并回收暂存文件；不得让未捕获异常、浏览器进程或大 Buffer 进入聊天进程。

`worker.queueLimit` 是管理员手动设置的共享排队上限。持久导出和临时截图按创建时间进入同一队列；
创建操作在串行状态事务中先处理幂等重试，再检查当前任务配置快照的上限，因此并发请求不能穿透
上限，已存在的同操作 ID 重试也不会被误拒。达到上限只对新的不同任务返回 `429`，运行中任务不变。

`worker.taskTimeoutMs` 不只包围浏览器渲染调用。任务进入 runner 后使用同一个取消信号覆盖输入准备、
Worker 执行、输出清单及哈希校验、提交前重新授权、配额检查和原子提交；排队等待时间不消耗该任务
快照的执行超时。Worker 尚在执行时发生超时或取消会终止对应进程组；Worker 已返回而任务处于输出
校验或提交阶段时，不再终止空闲 Worker，而是在下一个可取消边界中止该任务并清理暂存目录或尚未
提交的候选目录。已经原子 rename 完成的最终目录不回滚，提交后的通知失败也不改变成功结果。

既有 `/api/preview/capture` 也进入同一队列并共享截图并发、内存和超时设置。该兼容任务只在内存中
排队，不把带签名的预览 URL 写入持久任务记录；Worker 对入口及每个子请求重新校验 Origin、DNS
解析和受限地址。显式宽高必须分别落在 `320-32767` 和 `240-32767`，越界时明确失败，不夹值、不
回退渲染方式或降低画质。成功输出以临时文件流返回，响应结束或断开后立即回收，不提交到工程目录。

瓦片与图片缓存使用两个独立的管理员字节预算。缓存键绑定源文件真实路径、设备、inode、大小及
修改/变更时间；写入先复制到排他临时文件，复查源签名和长度，再原子 rename。跨 Worker 实例使用
缓存桶锁串行写入和裁剪，使并发完成后仍精确遵守各自预算。预览 HTTP 响应通过已打开的文件句柄
流式发送缓存文件或源文件，不把完整图片读入 Worker Buffer；缓存锁、复制或命中失败时只回退读取
原始工程文件，不改变渲染参数或输出质量。

每个任务暂存目录写入包含主站 PID 的所有权标记。启动恢复只删除所有者进程已经死亡的标记目录；
没有标记的旧版本目录只有在超过两小时后才按遗留项清理，`.cache`、存活蓝绿后端的任务和近期旧格式
目录均保留。管理员清缓存先取得 tile 与 image 两个跨进程桶锁，只删除这两个缓存桶中的文件，不删除
活动锁、工程源文件或任务暂存目录。

管理员可手动设置 Worker 开关、渲染/截图并发、内存预算、缓存、超时、空闲回收、预览与导出
参数、地图段大小和自动保存间隔。稳定、均衡、性能预设和自定义模式都只能人工切换。实时状态只
展示 CPU、可用内存、主站延迟、Worker 数、队列长度和当前手动预设，不触发任何设置变化。

暂停接收新任务不会终止运行任务；继续队列按原顺序调度。清缓存不能删除工程源文件、运行任务
输入或尚未原子提交的输出。

游戏预览或任何导出若遇到未保存编辑，必须先完成带版本校验的地图保存；保存失败或 `409` 时不创建
任务。任务固定绑定入队时的地图 SHA-256 和管理员设置快照。Worker 只写任务暂存目录，主站校验完整
文件清单、大小和 SHA-256 后，再把输出作为一个新目录原子提交到工程；`.git` 和 `.codex-*` 保留目录
不能作为输出根。请求尺寸、帧率、时长、格式或编码超出实现边界时只让任务失败，不能缩小参数、改变
格式或降低画质后继续。地图截图、游戏截图、全景、切片、动画帧、视频和批量子任务沿用同一约束。

## 验收与发布

验收至少覆盖 Tiled 往返及未知字段、有限/无限地图、外部 `.tsj`、图层与对象语义、编码 tile data、
嵌入式 Base64 资源和路径逃逸拒绝、跨用户/工程/窗口会话拒绝、分段读取版本漂移、乱序/重复/缺失 chunk、总哈希不符、
