# 新服务器引导部署实测记录（2026-07-20）

## 测试环境

- Ubuntu 24.04 LTS amd64，2 vCPU，约 3.8 GiB 内存，约 55 GiB 可用磁盘。
- 通过非标准端口 SSH 登录；应用端口始终只监听 `127.0.0.1`。
- 使用下载发布包，不配置 Git 远端，跳过 Codex 登录，选择本地/SSH 转发访问。

记录不包含服务器密码、网页登录密码、API 密钥或 SSH 私钥。

## 发现的问题

1. `v0.16.2` 从 `chatgpt.com` 下载 Codex 安装器时等待约 134 秒后失败，
   没有自动使用可访问的 npm registry。
2. 失败后重跑会重复执行 APT、NodeSource 和发布包内部清单检查。
3. Playwright 的 `--with-deps` 安装输出大量 APT/needrestart 进度，重跑还会
   再次执行依赖检查。
4. 目标网络访问 Playwright CDN 极慢，177 MiB Chromium 下载数分钟后只有
   约 1%，预估超过一小时；默认命令还会下载本项目不使用的 headless shell。
5. 30 分钟临时 SSH 授权不足以覆盖受限网络下的首次部署排障。

## 已验证的改进

- `v0.16.3` 在官方 Codex 地址两次约 5 秒连接超时后，自动从 npm 安装
  `codex-cli 0.144.6`；重跑正确跳过 APT，并且发布包 SHA-256 和内部提交清单
  各验证一次。
- 将同版本 Chromium 缓存经 SHA-256 核对后预置到服务器，完整发布测试、
  备份、蓝绿切换和 doctor 全部通过。
- 最终稳定网关监听 `127.0.0.1:4317`，活动后端监听 `127.0.0.1:4318`，
  公网地址没有监听 `4317-4319`。
- 安装器只读检查确认发布包来源、Codex CLI 和 app-server 均可用。

## v0.16.4 后续处理

- Playwright 系统依赖成功后写入私有检查点，重跑不再重复 APT。
- Chromium 使用 `--no-shell`，不再下载未使用的 headless shell；关闭刷屏进度，
  并设置 20 分钟硬超时，失败后给出缓存预置或修复 CDN 的明确提示。
- 临时 SSH 授权增加 30 分钟、1 小时和 2 小时选项，服务端仅接受这三个值，
  到期后继续主动关闭控制连接并清理密钥。

## 剩余限制

首次安装仍需要目标服务器能够在限定时间内下载 Chromium，或者事先放入与
`playwright-core` 修订号完全一致且带完成标记的缓存。当前发布包没有内置约
160 MiB 的浏览器缓存，因此在严格限速网络下不是完全离线安装。

## v0.16.5 供应商引导复验

- 安装向导新增 OpenAI 官方设备登录、Responses 兼容 API 供应商、稍后网页配置
  三种授权路径。
- 本地自动测试已覆盖供应商配置、加密文件 `0600` 权限、明文 Key 排除和失败回滚。
- 测试服务器已使用实际 Codex CLI 完成供应商分支、重复安装保留供应商、蓝绿
  切换和 doctor 复验；活动后端由 `4318` 切换至 `4319`，端口仍仅监听回环。
- 隔离状态目录内的随机假 Key 测试确认 Key 不进入输出、Codex TOML 或密文文件，
  供应商密钥与密文权限均为 `0600`。复验未发送会产生费用的真实模型提示。
